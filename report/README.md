# 기획서 (읽는 문서)

`docs/`는 **만드는 사람**을 위한 명세 26편이다. 여기 있는 건 다르다 —
**개발자가 아닌 사람이 처음부터 끝까지 한 번에 읽는** A4 19쪽 문서다.

읽는 사람이 개발자가 아니라는 게 제약 전부를 결정한다.

- **설명하는 순서로 쓴다.** 무슨 문제인가 → 왜 그게 문제인가 → 그래서 뭘 하려는가 →
  실제로 어떻게 생겼나 → 왜 그렇게 정했나. 결론부터 던지지 않는다.
- **그림이 먼저다.** "글을 쓰면 흐름도가 된다"는 글로 전달되지 않는다.
  3장은 쓰는 화면 · 그려진 흐름도 · 질문 카드 · 요약 카드를 실제로 보여준다.
  전부 HTML/SVG라 인쇄에서도 깨지지 않는다.
- **용어를 안 쓴다.** `.tsx`·수직 스켈레톤·XOR/AND·파싱·리드타임·북극성 지표는
  전부 풀어 썼다. `docs/`에서 문장을 옮겨올 때 이게 가장 자주 걸린다.

| 파일 | 무엇 |
|---|---|
| `기획서.pdf` | 배포용. A4 19쪽, 쪽번호·목차 포함 |
| `plan.html` | 원본. 화면(라이트/다크)과 인쇄를 같은 파일이 담당한다 |
| `print.mjs` | CDP로 PDF를 뽑는다 |
| `paginate.mjs` | 목차 쪽번호를 실제 PDF에서 읽어 되쓴다 |

## 다시 뽑기

```bash
cd report
node print.mjs    "$PWD/plan.html" "$PWD/기획서.pdf"   # 1차
node paginate.mjs "$PWD/plan.html" "$PWD/기획서.pdf"   # 목차 쪽번호 확정
node print.mjs    "$PWD/plan.html" "$PWD/기획서.pdf"   # 2차 — 이게 최종본
```

**왜 두 번 뽑나.** 목차 쪽번호는 조판 전에 알 수 없다. 손으로 적으면
문단 한 줄만 늘어도 조용히 틀린다 — 이 저장소가 `scripts/doc-numbers.mjs`로
막고 있는 것과 정확히 같은 종류의 거짓말이다. 그래서 1차 PDF에서
`pdftotext`로 각 절이 실제로 시작하는 쪽을 읽어 HTML에 되쓰고 다시 뽑는다.
찾지 못하면 **에러로 죽는다.** 빈칸(`—`)이 하나라도 남으면 그것도 에러다.

절 제목을 이 스크립트에 적어 두지 않는 이유도 같다. 적어 두면 문서를 고칠 때마다
같이 고쳐야 하고, 안 고치면 스크립트가 문서보다 낡는다.

## 필요한 것

- Chrome (`/Applications/Google Chrome.app`) — 헤드리스로 CDP 인쇄
- `pdftotext` · `pdfinfo` (poppler) — 쪽번호 확정용

Chrome CLI의 `--print-to-pdf`는 머리말/꼬리말 템플릿을 받지 못해서
쪽번호를 넣을 수 없다. 그래서 CLI 대신 CDP `Page.printToPDF`를 쓴다.

## 문서 안의 숫자

이 문서가 주장하는 숫자(상세 문서 26편 · 자동 점검 784가지 · 결정 79건)는
`scripts/doc-numbers.mjs`가 실제 값과 대조한다. **PDF가 아니라 `plan.html`을 잡는다** —
PDF는 CI가 열어볼 수 없고, 숫자가 어긋난 채 재생성되면 그건 저장소 밖으로
나가는 문서라 되돌릴 수 없다.

문장을 고치면서 그 숫자 표현까지 바꾸면 `npm run verify`가
*"주장을 못 찾았다"*로 죽는다. 그때 `doc-numbers.mjs`의 정규식도 같이 고친다.
