# workflow-builder

> 가칭. 이름 후보는 [PRD §5.4](./docs/PRD.md) 참조 (유력: **Preflow**)

**직원은 "설명하지 않아도 되는 업무 문서"를 얻고, 회사는 "직원이 직접 만든 자동화 백로그"를 얻는다.**

n8n·Zapier 같은 자동화 도구를 열기 전에 필요한 것 — 비개발자가 자기 업무 흐름을 빠르게 기록하면 다이어그램이 자동 생성되고, 어디를 자동화(혹은 제거)할지 드러나는 도구.

## 어떻게 다른가

| | 한계 |
|---|---|
| 프로세스 마이닝 (Celonis 등) | 시스템 로그가 없는 업무는 못 봄. 진입 1.5억 원~ |
| 태스크 마이닝 (Scribe 등) | 브라우저 밖(전화·오프라인 승인·카톡·부서 간 대기)을 못 봄 |
| 다이어그램 툴 (Miro 등) | 그림만 남고 데이터가 안 쌓임 |
| 컨설팅 | 1회성. 끝나는 날이 문서 사망일 |

→ 로그에도 화면에도 남지 않는 업무. 유일한 데이터 소스는 **당사자의 기억**이고, 그걸 구조화해 수집하는 제품은 사실상 없다.

## 핵심 설계

- **입력은 글처럼, 출력은 그림으로.** 사용자는 선을 단 한 번도 직접 긋지 않는다
- **빈 화면을 주지 않는다.** 붙여넣기 파싱 → 질문 연쇄 → 아웃라인+다이어그램
- **작성 중에는 메타데이터를 묻지 않는다.** 다 쓰고 나서 카드 스택으로
- **관리자에게 개인 데이터를 보여주지 않는다.** 정책이 아니라 코드로 못박음

## 코드

```
packages/graph-core/     graph = derive(tree) ⊕ overrides
                         런타임 의존성 0 · React·DB·DOM 의존 없음 (타입 시스템으로 강제)
                         골든 픽스처 36 + 불변식 12 + 스모크 9 = 57건 통과
```

```bash
cd packages/graph-core
npm i && npm test && npm run typecheck
```

## 상태

기획 완료, 구현 착수 전. `graph-core`만 선행 구현.

기획은 **20개 관점의 독립 전문가 검토**를 종합해 작성되었다 — PM · 조직 도입 · UX 리서치 · BPM/프로세스 마이닝 · 시장 분석 · 기술 아키텍처 · 비주얼 디자인 · 정보 시각화 · UX 라이팅 · 화면 설계 · 컴포넌트 · 시드 콘텐츠 · 접근성 · 애널리틱스 · 파싱 알고리즘 · 그래프 알고리즘 · 문서 생성 · 엔티티 레졸루션 · 보안 거버넌스 · 제품 정책.

전문가 간 의견이 충돌한 지점과 그 해소 근거는 [DECISIONS.md](./docs/DECISIONS.md)에 **결정 59건**으로 기록되어 있다. 각 결정에는 **"뒤집는 조건"**이 붙어 있다 — 그게 비어 있는 결정은 무엇을 가정하는지 모른다는 뜻이므로.
