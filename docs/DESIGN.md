# 디자인 시스템

> 최종 갱신: 2026-08-17 · 상태: 초안 v0.1

이 제품에서 디자인은 마감이 아니라 **기능**이다. 이유는 둘이다.

1. **"회사가 시킨 시스템"처럼 보이면 그 순간 끝난다.** 감시 도구 낙인은 카피가 아니라 시각적 톤에서 먼저 결정된다.
2. **결과물이 남에게 공유된다.** 예뻐야 공유하고, 공유돼야 확산된다. 열람자/작성자 3:1이 유일한 성장 루프이므로 **디자인이 곧 바이럴 계수**다.

---

## 1. 디자인 원칙 5개

### 원칙 1 — "내 문서"지 "시스템 레코드"가 아니다
시각적 기본형은 폼(form)이 아니라 문서(document). 아웃라인 패널은 테이블/리스트가 아니라 여백이 넉넉한 편집기로 그린다.
→ **필드 라벨("업무명", "소요시간") 인쇄 금지.** 라벨이 붙는 순간 신청서가 된다. 플레이스홀더와 인라인 자연어로 대체.

### 원칙 2 — 집계는 그리지 않는다
**전 화면 금지 토큰**: % 게이지, 도넛 차트, 진행률 바, 리더보드, 팀 평균 비교.
→ 시간은 숫자가 아니라 칩("반나절")으로만 존재하고 합계를 계산해 보여주지 않는다.
→ `12단계`는 허용(중립적 사실). `완료율 67%`는 불허(**평가**).

> 예외: 우상단 완성도 링(단계 수/담당자/시간 채움률)은 **본인만 보는 잠금해제 신호**로 허용. 팀 비교·순위와는 절대 결합하지 않는다.

### 원칙 3 — 색은 판단하지 않고 분류만 한다
신호등(빨강/노랑/초록) 체계를 노드에 절대 쓰지 않는다.
→ 감정·강도는 색 대비가 아니라 **도트 개수**(`●●○○`)로. 도트는 단일 hue — 즉 **"많이 번거로움"도 초록**이다. 감정은 상태가 아니라 정보라는 걸 색이 말하게 한다.
→ 빨강은 **파괴적 액션(삭제 확인) 한 곳에만** 등장한다.

### 원칙 4 — 최종 산출물이 화면보다 예뻐야 한다
편집 화면은 도구답게 조용하지만, 내보낸 PNG와 공유 페이지는 별도 디자인을 갖는다. 그림자 제거, 보더 1.5px, 여백 48px, 종이색 배경 — 슬라이드에 붙였을 때 "남의 툴 스크린샷"으로 보이지 않게.

### 원칙 5 — IT 숙련도 편차를 밀도로 흡수한다
| 경로 | 밀도 | 컨트롤 높이 | 본문 |
|---|---|---|---|
| 작성 (온보딩·질문 연쇄·카드 스택) | 저밀도 | 44px | 16px |
| 반복 사용 (아웃라인·캔버스) | 중밀도 | 32~36px | 15px |
| 고밀도(28px) | 쓰지 않음 | | |

## 2. 톤앤매너

**되어야 하는 것**: 침착한 · 정돈된 · 종이 같은 · 사려 깊은 · 어른스러운.
감각 레퍼런스: *잘 만든 만년필 노트 + 정갈한 사무용 소프트웨어.*

**절대 안 되는 것 3종**

| | 증상 |
|---|---|
| 그룹웨어·ERP | 파란 헤더 바, 그리드 테이블, 결재선 UI, 뱃지 남발, 아이콘 툴바 20개 |
| 게임화된 유치함 | confetti, 뱃지, 레벨, 스트릭, 마스코트 |
| 실리콘밸리 AI 스타트업 | 보라 그라디언트, 글래스모피즘, ✨ 스파클, "AI가 분석 중…" 펄스 |

> **confetti 금지 이유**: 자동화 후보를 찾았을 때 축하 애니메이션은 최악이다 — **실직 공포를 정확히 자극한다.**

### "감시받는 느낌"을 제거하는 5가지 장치

1. 상단바 좌측에 **자물쇠 + "나만 보기"** 상시 노출. 공유는 명시적 버튼을 눌러야만 발생한다는 시각적 보증
2. **조회자 아바타 스택("3명이 봤습니다") 절대 금지.** 조회 로그 UI 자체를 만들지 않는다
3. 관리자 대시보드로 가는 링크를 일반 사용자 화면에 노출하지 않는다(존재하더라도)
4. 문서 헤더는 "영업팀 프로세스 #A-12"가 아니라 **"지수님의 견적서 발행 흐름"**. 조직 계층 트리 UI 없음
5. 결과 화면은 순위 리스트가 아니라 카드 2~3장. 근거 설명은 접힌 상태(추궁이 아니라 제안)

## 3. shadcn/ui 탈출

shadcn 기본값의 지문 4가지 — 균일한 `--radius: 0.5rem`, `shadow-sm` 남발, `ring-2 ring-offset-2` 포커스, `h-9 text-sm` 컨트롤. 넷 다 갈아엎는다.

```css
:root {
  /* radius — 균일 금지, 5단계 차등 */
  --radius-xs: 4px;     /* 뱃지, 인풋 내부 요소 */
  --radius-sm: 6px;     /* 버튼, 인풋, 셀렉트 */
  --radius-md: 12px;    /* 카드, 캔버스 노드 */
  --radius-lg: 14px;    /* 패널, 다이얼로그 */
  --radius-full: 999px; /* 부서 칩, 시작·종료 pill */

  /* 그림자 대신: 잉크 보더 + inset 하이라이트 */
  --edge-flat:  inset 0 1px 0 rgb(255 255 255 / .55);
  --edge-raise: 0 1px 0 rgb(28 27 25 / .04), inset 0 1px 0 rgb(255 255 255 / .7);
  /* 실제로 떠 있는 것만 진짜 그림자 */
  --shadow-float: 0 1px 2px rgb(28 27 25/.06), 0 8px 24px -8px rgb(28 27 25/.16);
  --shadow-drag:  0 2px 4px rgb(28 27 25/.08), 0 16px 32px -12px rgb(28 27 25/.22);

  --control-h-sm: 32px; --control-h-md: 36px; --control-h-lg: 44px;
  --space-base: 4px;  /* 8px 그리드 아님 */
}
```

- **보더 처리** — 모든 서피스는 그림자 0, `1px solid var(--border-subtle)`. 캔버스 노드만 1.5px(줌아웃 시 hairline 소실 방지). 패널 구분은 보더가 아니라 **배경색 차이**로 만들고 경계에만 1px
- **버튼 무게** — Primary는 브랜드색이 아니라 **잉크 `#1C1B19`** 배경 + `--edge-raise`. 그린은 잉크보다 아껴 쓴다. 높이 36px, padding 14px, weight 600, `letter-spacing: -0.01em`
- **인풋** — `ring-offset` 이중 링 폐기. 포커스는 `border-color: #2A7358` + `box-shadow: 0 0 0 3px rgb(42 115 88 / .14)` 단일 소프트 링
- **밀도** — base 4px. 아웃라인 블록 상하 padding 10px, 블록 간 gap 4px, 섹션 간 24px. 온보딩만 `data-density="comfortable"`

## 4. 컬러

> **두 디자이너의 팔레트가 충돌했다** — 비주얼 디자인은 "파랑 금지 + 따뜻한 종이 회색", 다이어그램 디자인은 파랑 액센트 + 쿨 그레이를 제안했다.
> **판단**: 팔레트 정체성(감시 느낌 제거)은 제품 생존에 직결되므로 비주얼 쪽을 채택하고, 다이어그램 노드 색을 여기에 재매핑했다.

### 브랜드 — 딥 에버그린

파랑은 "회사 시스템", 보라는 AI 클리셰, 주황은 경고와 충돌, 밝은 민트(#10B981)는 헬스케어·핀테크 클리셰. → 초록을 **채도 낮추고 어둡게**.

```
brand-700  #16452F   oklch(.35 .055 158)
brand-600  #1F5C46   oklch(.42 .060 160)   ← 주 액센트 (흰 배경 7.84:1, AAA)
brand-500  #2A7358   oklch(.50 .068 161)   ← 포커스 링, 링크 (5.69:1, AA)
brand-100  #DDEDE5
brand-50   #EEF6F1                          ← 결과 하이라이트 배경
```

### 중립 — 순수 회색 금지, 따뜻한 종이 회색

hue 85~95, chroma 0.004~0.010. **순수 그레이는 화면을 즉시 "시스템"으로 만든다.**

```
n-0   #FFFFFF    n-25  #FCFBF9 (앱 배경)   n-50  #F7F6F3 (캔버스)
n-100 #F0EEEA    n-200 #E4E1DB            n-300 #D2CEC6
n-450 #948F87 ★  n-550 #6F6A62 ★
n-700 #45423D    n-900 #1C1B19 (본문·잉크 버튼 17.2:1)
```

### ⚠️ 대비 검증 — 초기 팔레트의 결함 3건과 수정

접근성 검토에서 초기값 일부가 WCAG를 통과하지 못하는 것이 확인됐다. **모든 수치를 sRGB 상대휘도로 재계산해 정정했다.**

| 조합 | 초기 기재 | 실측 | 판정 |
|---|---|---|---|
| `#1F5C46` on 흰색 | 8.1:1 | **7.84:1** | AAA ✓ (수치만 정정) |
| `#2A7358` on 흰색 | 6.2:1 | **5.69:1** | AA ✓ (수치만 정정) |
| `#1C1B19` on 흰색 | 15.8:1 | **17.21:1** | ✓ |
| `#6E4666` (기다림) on 흰색 | 7.0:1 | **7.69:1** | ✓ |
| ~~`#7C7770`~~ (보조 텍스트) on `#FCFBF9` | 4.9:1 | **4.29:1** | ❌ **AA 미달** |
| ~~`#A8A39A`~~ (placeholder) on `#FCFBF9` | — | **2.43:1** | ❌ **심각** |
| ~~`#A56A12`~~ (분기) on 흰색 | 4.7:1 | **4.50:1** | ⚠️ 임계값 정확히 걸침 |
| `#E4E1DB` (보더) on `#FCFBF9` | — | **1.26:1** | ❌ 1.4.11 미달 |

**`#A8A39A` placeholder가 가장 심각하다.** 이 제품에서 placeholder는 장식이 아니라 **주 안내문**이다 — "여기에 무엇을 하는지 쓰세요", "예: 금액이 500만 원을 넘으면". 그게 2.43:1이면 40~50대 사무직에게는 사실상 보이지 않는 텍스트다. 사용자층을 생각하면 이건 접근성 위반 이전에 **제품 실패**다.

**정정된 토큰**

```
n-550  #6F6A62   보조 텍스트 · 캡션 · placeholder 전용
                 5.19:1 on n-25 / 4.96:1 on 캔버스 — 양쪽 다 AA ✓
n-450  #948F87   인풋·버튼·컨트롤 경계선 전용
                 3.11:1 — 비텍스트 3:1 ✓
branch #9E6511   분기 액센트 (4.86:1) — #A56A12는 4.50으로 임계에 정확히 걸려
                 렌더링·안티에일리어싱 편차에 취약하므로 여유를 둔다
```

**강등**

| 토큰 | 새 용도 |
|---|---|
| `n-400 #A8A39A` | **텍스트 색에서 완전 퇴출.** 도트 그리드 등 순수 장식만 |
| `n-200 #E4E1DB` | 면 구분용만. **인풋·버튼 경계선으로 쓰지 않는다** → `n-450` |
| `n-300 #D2CEC6` | 고스트 노드 등 장식 보더만 |
| `n-500 #7C7770` | 흰 배경(`#FFFFFF`) 위에서만 허용. 따뜻한 배경 위에서는 `n-550` |

**CI 강제**: Stylelint 규칙으로 `n-400`·`n-200`이 `color` / `border-color` 속성에 등장하면 빌드 실패.

**포커스 링은 이중 링으로 고정** — 잉크 버튼(어두움) 위에서도 3:1을 보장해야 한다.
```css
box-shadow: 0 0 0 2px var(--n-25), 0 0 0 4px var(--brand-500);
```

### 노드 타입 3종

**형태(마름모)로 구분하지 않는다.** 한글 텍스트가 마름모에 들어가면 줄바꿈이 처참하고, 텍스트 가용 면적이 bounding box의 50%다. ELK layered도 직사각형 포트 모델을 전제한다.

구분은 3중 인코딩 — ① 좌측 3px 액센트 바 ② 좌상단 16px 라인 아이콘 ③ 실루엣 변형. **색은 절대 단독 신호가 아니다**(색맹 대응).

| | 작업 `task` | 분기 `branch` | 기다림 `hold` | 시작·종료 |
|---|---|---|---|---|
| 액센트 바 | 없음 (기본) | `#9E6511` | `#6E4666` | — |
| 보더 | 1px `n-200` | 1px `n-200` | **1.5px dashed `n-450`** | — |
| 실루엣 | 평범 | **하단 중앙 노치** (폭 16, 깊이 7) | 대시 보더 | pill |
| 아이콘 | square-check | git-branch | clock | play / flag |
| 대비 | — | 4.86:1 AA | 7.69:1 | — |

**줌 아웃 시 3중 인코딩이 무너지는 지점** — `z < 0.45`에서 아이콘이 사라지고, 노치는 폭 16px이라 0.3배에서 4.8px가 되어 소실된다. 색만 남으면 색맹 사용자에게 구분이 불가능하다.

| 줌 | 보정 |
|---|---|
| `z < 0.45` | `hold`의 대시 길이를 줌에 반비례해 확대 (`strokeDasharray = 6/z`) |
| `z < 0.45` | `branch`의 액센트 바 폭 3px → **5px**, 상단 모서리만 radius 2px로 실루엣 차이 확대 |
| 흑백 인쇄 | 액센트 바를 **패턴**으로 치환 — task 없음 / branch 실선 / hold 3px 점선. 내보내기 푸터에 범례가 이미 있으므로 학습 비용 0 |

**검증 방법**: Chrome DevTools → Rendering → Emulate vision deficiencies 4종(protanopia / deuteranopia / tritanopia / achromatopsia) + `filter: grayscale(1)` 스크린샷을 CI 아티팩트로 남긴다.

```
danger  #B4342B   — 삭제 확인 다이얼로그 전용
info    없음      — 파랑을 쓰지 않는다. 안내는 n-100 배경 + n-700 텍스트
```

### 😤 짜증 플래그 — 렌즈 전용

빨강으로 칠하면 즉시 "오류/잘못됨"으로 읽힌다. 그리고 원칙 3과 충돌한다.

→ **캔버스 기본 렌즈에서는 표시하지 않는다.** 짜증 렌즈에서만 나타난다(§6). 인스펙터의 감정 칩은 뉴트럴 배경 + 도트 4개 강도 표시.

### 다크모드 — P2

사무직의 다크모드 채택률은 개발자 대비 현저히 낮고, 이 제품의 산출물은 캡처·인쇄·슬라이드 삽입이라 **라이트가 기본 매체**다.

단, 토큰을 값이 아니라 **의미로 네이밍**(`--surface-canvas`, `--border-subtle`, `--text-secondary`)해서 나중에 팔레트만 교체 가능하게 한다.
**예외**: 공유 페이지 `/s/[id]`만 `prefers-color-scheme` 대응 — 남의 다크 브라우저에서 열릴 확률이 높다.

다크 팔레트 초안(P2 착수 시):
```
canvas #0C111D   card #161B26 (배경보다 밝게 — elevation을 그림자가 아니라 명도로)
border #2A313C 1px + inset 0 1px 0 rgba(255,255,255,.04)
text   #ECEFF3 (순백 금지)   sub #94A0B4
액센트는 채도를 낮추고 명도를 올린다. 엣지는 1.5 → 1.75px (어두운 배경에서 얇은 선은 더 얇게 지각됨)
내보내기는 항상 라이트 강제가 기본값. 다크 PDF는 인쇄·문서 임베드에서 파탄난다
```

## 5. 한글 타이포그래피

### 폰트: Pretendard Variable, 자체 호스팅

Wanted Sans는 기하학적 골격 때문에 "IT 스타트업" 톤이 붙어 전 직원용 도구엔 리스크. SUIT는 라틴 대비 한글 크기 밸런스가 UI 소자에서 불안정. Pretendard는 라틴-한글 시각 크기 균형이 가장 잘 잡혔고 dynamic subset과 variable을 공식 배포한다.

**차별화는 폰트 교체가 아니라 자간·행간 체계로 만든다.**

```
1) woff2-dynamic-subset 92분할 → /public/fonts + @font-face 92개
   (단일 1.2MB variable 대신, 실제 로딩량 화면당 40~80KB)
2) next/font/local 로 등록, font-display: swap
   fallback: -apple-system, "Apple SD Gothic Neo", "Malgun Gothic", sans-serif
   size-adjust / ascent-override 로 fallback 레이아웃 시프트 제거
3) OG 이미지(satori)는 dynamic subset 불가
   → 완성형 2,350자 정적 subset (Regular/Bold, 각 ~90KB) 별도 준비
```

### 타입 스케일 (16px root)

핵심: 한글은 네모틀이라 **작은 크기에서 음수 자간이 가독성을 크게 해친다.** 대부분의 한국 UI가 전 크기에 `-0.02em`을 무비판적으로 거는데, 크기별로 다르게 준다.

| 역할 | size / line-height | letter-spacing | weight |
|---|---|---|---|
| 온보딩 질문 | 28px / 1.32 | **-0.025em** | 700 |
| 문서 제목 | 22px / 1.36 | -0.020em | 600 |
| 섹션 | 18px / 1.45 | -0.015em | 600 |
| 본문·아웃라인 | 15px / 1.65 | -0.005em | 400 |
| 본문 강조 | 15px / 1.65 | -0.005em | **600** |
| 노드 타이틀 | 15px / 1.45 | -0.010em | 600 |
| 라벨·칩 | 13px / 1.50 | **0em** | 500 |
| 캡션 | 12px / 1.50 | **+0.005em** | 500 |

추가 규칙:
- **Pretendard 500은 한글에서 400과 거의 구분되지 않는다 → 강조는 항상 600.** 700은 온보딩 질문에만
- 전역 `word-break: keep-all; overflow-wrap: anywhere;` — 한글 어절 단위 줄바꿈
- 숫자·시간은 `font-variant-numeric: tabular-nums`
- **본문 행간 1.65** — 라틴 UI 표준 1.5보다 높다. 한글 세로 밀도 보정

## 6. 다이어그램 스펙

### 6.1 노드

```
크기      260 × 76px  (폭은 240 / 260 / 300 3단계 스냅만 허용)
radius    12px
배경      #FFFFFF
그림자    0 1px 2px rgba(28,27,25,.06)  — 한 겹만. 2겹 이상은 50노드에서 화면이 뿌예짐
패딩      14px 16px 14px 19px           — 좌측 액센트 바 3px 보정
텍스트    좌측 정렬 고정                 — 중앙 정렬은 2줄이 되는 순간 들쭉날쭉
제목      15px / 1.45 / 600 / -0.01em / n-900
          -webkit-line-clamp: 2 (한글 약 34자) → 잘리면 hover 툴팁 전문
hover     보더 n-400
selected  2px brand-500 + ring 4px rgb(42 115 88 / .12)
```

**ELK에 넘기는 노드 크기는 렌즈·줌과 무관하게 항상 260×76 고정.** 이게 레이아웃 안정성의 전제다.

### 6.2 메타데이터 — 3슬롯 + 렌즈 + 인스펙터

핵심 규칙: **카드에 상시 노출되는 메타는 최대 3슬롯, 높이는 절대 변하지 않는다.**

카드 하단 24px는 "메타 스트립"으로 고정 예약. 메타가 없으면 빈 채로 둔다.
> 높이 변동 = ELK 재계산 = 위치 흔들림 = 멘탈 모델 파괴

슬롯 우선순위: **담당자 > 소요시간 > 도구**. 빈도는 카드에 절대 올리지 않는다(변화가 적고 흐름 판독에 기여 안 함) — 인스펙터 전용.

| 메타 | 표현 |
|---|---|
| 담당자 | 20px 원형 이니셜 아바타(한글 성+이름 첫 자, 11px). 사진 없음. 배경은 이름 해시 → 채도 낮은 8색 (**의미가 아니라 식별자**) |
| 도구 | **로고를 쓰지 않는다** — Slack·Microsoft 브랜드 가이드가 아이콘화·색배경 배치를 금지하고, 로고 채도(#4A154B, #217346)가 타입 액센트를 잡아먹는다. → 12px 단색 라인 아이콘(자체 제작) + 텍스트 칩. `h20 / p2-7 / r6 / bg n-100 / 11px n-700`. 3개 초과는 `+2`로 접기 |
| 소요시간 | 텍스트가 아니라 **4단계 막대** (1×3px 세그먼트 4개). "반나절"보다 스캔이 빠름 |
| 자동화 가능 | 좌하단 12px 스파클 `brand-500` |
| 😤 짜증 | **기본 렌즈에서 표시 안 함.** 짜증 렌즈 전용 |

**3단 위계**: 카드(3슬롯) → hover 300ms 후 240px 팝오버(전체 메타) → 클릭 시 우측 360px 인스펙터(캔버스는 안 움직임).

### 6.3 렌즈 (view mode) — 5종

**렌즈 전환 시 노드 위치는 1px도 움직이지 않는다.** 바뀌는 것은 메타 스트립 내용, 채도, 엣지 강조뿐. 200ms `cubic-bezier(.2,.8,.2,1)` 크로스페이드.

| 렌즈 | 내용 |
|---|---|
| **흐름** (기본) | 메타 스트립 비움. 제목과 타입만. 첫 화면은 항상 이것 |
| **사람** | 아바타+이름. 인계 엣지 `2px #6E4666`로 승격, 나머지 `opacity .5`. 같은 담당자 연속 구간에 좌측 세로 레일 |
| **시간** | 시간 막대+텍스트. 카드 우측 끝 3px 세로 바(높이=시간 비례). 헤더에 총 리드타임. "하루 이상"만 보더 `1.5px #A56A12` |
| **도구** | 도구 칩 전량(4개까지). 같은 도구 노드끼리 hover 시 연결 하이라이트 → **도구 전환 횟수가 눈에 보임** |
| **짜증** | 플래그 노드만 tint 배경 + 보더 강조, 나머지 `grayscale(1) opacity .45`. **회고 미팅에서 스크린샷 찍히는 화면이 이것** |

### 6.4 엣지

```
라우팅    직교(orthogonal) + 12px 라운드 코너
          React Flow: type 'smoothstep', pathOptions { borderRadius: 12, offset: 16 }
          베지어는 분기 3개 이상에서 곡선끼리 겹쳐 추적 불가능해짐
stroke    1.5px n-400   hover/selected 2px n-700   (절대 3px 이상 금지)
화살표    MarkerType.ArrowClosed, 14×14, 노드 경계에서 4px 띄움
          열린 화살표(V자)는 축소하면 사라짐
```

**분기 라벨**: 흰 pill(`p3-8 / r6 / 12px 500 n-700 / border 1px n-200`). 배치는 선 중점이 아니라 **분기 노드에서 나온 직후 첫 수직 세그먼트의 24px 아래** — 여기는 항상 다른 엣지가 없는 안전지대. 최대 14자, 초과 시 말줄임+툴팁.

**인계 마커**: 엣지 중점에 10px 원(흰 채움, 1.5px `#6E4666` 보더) + 6px 화살표 교차 아이콘. 사람 렌즈에서는 20px로 커지며 `이전 아바타 → 이후 아바타` 미니 칩으로 확장. **선 자체의 색·굵기는 건드리지 않는다** — 그래야 소음이 안 된다.

**부서 경계**: 엣지에 마커를 더 얹지 않는다. 레이아웃 레벨의 **부서 구간 배경 그룹**으로 처리하고, 경계를 넘는 엣지만 라벨 pill에 부서명(`영업 → 재무`). **엣지에 신호를 2개 이상 얹으면 둘 다 안 보인다.**

### 6.5 레이아웃 — 위→아래(TB) 고정

근거: (1) 한글 라벨은 260px 폭에 2줄로 수렴해 노드가 세로로 두툼하다 → 가로 흐름은 세로 여백만 낭비 (2) 스크롤 방향과 흐름 방향이 일치해 "읽는다"는 감각 (3) 최종 산출물이 A4 세로 PDF와 노션 임베드.

```js
'elk.algorithm': 'layered',
'elk.direction': 'DOWN',
'elk.layered.layering.strategy': 'NETWORK_SIMPLEX',
'elk.layered.nodePlacement.strategy': 'BRANDES_KOEPF',
'elk.layered.nodePlacement.bk.fixedAlignment': 'BALANCED',
'elk.layered.crossingMinimization.strategy': 'LAYER_SWEEP',
'elk.layered.considerModelOrder.strategy': 'NODES_AND_EDGES',   // ★ 필수
'elk.layered.crossingMinimization.forceNodeModelOrder': 'true',
'elk.layered.crossingMinimization.semiInteractive': 'true',      // ★ 이전 좌표를 시드로
'elk.edgeRouting': 'ORTHOGONAL',
'elk.layered.mergeEdges': 'true',
'elk.spacing.nodeNode': 40,
'elk.layered.spacing.nodeNodeBetweenLayers': 64,
'elk.spacing.edgeNode': 24,
'elk.edgeLabels.inline': false,
'elk.spacing.edgeLabel': 8,
'elk.hierarchyHandling': 'INCLUDE_CHILDREN',
```

`considerModelOrder`가 핵심이다. **사용자가 "먼저 이거, 아니면 저거"라고 쓴 순서가 갈래의 좌우 순서로 그대로 나와야 "내 글이 그림이 됐다"는 감각이 생긴다.**

- **분기 배치**: `BALANCED` 대칭. 단 **정상 경로(첫 번째로 쓴 갈래)를 항상 최좌측**에 고정하고 그 갈래만 stroke를 반 톤 진하게 — 눈이 기본 경로를 먼저 따라간다
- **갈래 5개 이상**: 대칭 유지 시 폭 1500px로 화면 이탈. 4개 초과 시 **팬아웃 스택 모드** — 갈래를 세로로 쌓고 각 서브그래프만 `elk.direction: 'RIGHT'` 오버라이드(ELK는 자식 그래프별 direction 지원). 빗살 형태로 2컬럼 이내

### 6.6 레이아웃 안정성 (사용성의 절반)

> 타이핑할 때마다 노드가 춤추면 즉시 신뢰를 잃는다. 이건 나중에 붙이는 최적화가 아니라 **1주차 설계 항목**이다.

1. **타이핑 중에는 절대 재배치하지 않는다.** 트리거는 오직 구조 변경 — Enter로 줄 생성/삭제, 분기 생성/삭제, 순서 이동, blur. 텍스트 편집은 라벨만 갱신하고 **노드 폭은 고정**이라 글자 길이가 레이아웃을 흔들지 못한다. *이거 하나로 어지러움의 80%가 사라진다*
2. **구조 diff 게이트** — 노드·엣지 집합의 해시를 비교해 위상이 동일하면 레이아웃을 아예 돌리지 않는다. 타이핑의 95%가 여기서 걸러짐
3. **디바운스는 조합 인지형** — 위상 변경 시에만 trailing 300ms, `compositionstart`가 오면 타이머 취소 후 `compositionend`에 재무장
4. **활성 노드 앵커링** — ELK 결과를 그대로 적용하지 않고, 방금 편집한 노드의 **화면 좌표가 변하지 않도록** 캔버스 전체를 역보정 translate. 시선이 고정된 지점은 안 움직이고 주변만 재정렬 → "통제 상실"이 아니라 "정리되는 느낌"
5. **스테일 결과 폐기** — 요청마다 단조 증가 revision, `if (res.revision !== latest) return`
6. **큰 재배치는 예고** — 바운딩 박스가 15% 이상 변하면 3초 토스트 "그림을 다시 정리했어요 [되돌리기]". 우상단 `🔒 배치 고정` 토글 제공

### 6.7 밀도와 스케일

| 단계 수 | 전략 |
|---|---|
| ~5 | `fitView({ maxZoom: 1.0, padding: 0.25 })`. maxZoom 상한이 없으면 카드가 화면 절반을 차지하는 괴물이 됨. 노드 4개 이하는 세로 40% 지점 정렬 |
| ~50 | 담당자·부서가 같은 **연속 구간을 자동 그룹**으로 묶어 ELK 서브그래프 컨테이너 렌더. 접으면 단일 요약 노드("영업팀 · 6단계 · 약 2시간"). 접기 상태는 URL에 저장해 공유 링크에 반영 |
| 200+ | `onlyRenderVisibleElements`, `content-visibility: auto`, 노드 `React.memo`, `nodeTypes`는 **모듈 스코프 상수** |

**Semantic zoom 4단계** — 사라지는 순서의 원칙:
> **속성(도구·시간) → 식별(이름) → 관계 주석(엣지 라벨) → 내용(제목) → 구조(타입·위치)는 끝까지 남는다.**

```
z ≥ 0.75          전체
0.45 ≤ z < 0.75   도구 칩·시간 막대 제거, 아바타 유지, 엣지 라벨 유지
0.30 ≤ z < 0.45   담당자 이름 제거(아바타만), 엣지 라벨 제거, 제목 1줄 clamp
z < 0.30          제목까지 제거 → 60×20px 색 블록 + 좌측 3px 액센트만
```

미니맵은 노드 20개 이상일 때만 우하단 200×140.

### 6.8 빈 상태와 성장

- 단계 1개여도 **시작 pill → 노드 → 종료 pill**을 이미 그려준다. 완결된 작은 문서로 보인다
- 마지막 노드 아래 **고스트 노드**: `260×76 / 1.5px dashed n-300 / transparent / 중앙 13px n-400 "다음 단계를 적어보세요"`. **빈 공간이 결핍이 아니라 초대가 된다**
- 캔버스 여백은 도트 그리드(`n-200`, 1px @ 24px, opacity .5) + 옅은 중앙 비네트로 "의도된 여백"처럼
- 우상단 **완성도 링** — 단계 수 / 담당자 채움률 / 시간 채움률을 24px 도넛 3개로. 3단계 33%가 눈에 보이면 계속 쓰게 됨 (원칙 2 예외 조항)

- 아웃라인 좌 42%(min 380 / max 560px), 캔버스 우 나머지
- 리사이즈 핸들 시각 1px / 히트 8px, 드래그 중에만 `brand-500`
- 스냅 360 / 440 / 560px, 폭은 localStorage 저장
- 캔버스 배경 `n-50` + 24px 도트 그리드

**반응형** — 사무직은 넓은 모니터를 쓰지만 창을 반씩 나눠 쓴다. **720px 폭에서도 2패널이 깨지지 않아야 한다.**

| 폭 | 처리 |
|---|---|
| ≥ 1024px | 2패널 |
| 768~1024px | 상단 세그먼트 컨트롤 (아웃라인 \| 다이어그램) |
| < 768px | 아웃라인 작성 전용 + 다이어그램은 바텀시트 미리보기 (현장·물류 직원이 폰으로 적는 시나리오 실재) |

**초심자 배려**: 처음부터 2패널을 동시에 보여주면 주의가 분산된다. 첫 3단계까지는 다이어그램을 우하단 240px 미니 프리뷰로 두고, 4번째 단계에서 "그림이 커지고 있어요" 하며 확장.

### 공유 페이지 `/s/[id]`

- 상단: 제목 22px + 부서 칩 + `12단계 · 약 3분`
- 다이어그램은 높이 560px 고정 프레임, 초기 fit-to-view, 우하단 확대/축소 2개만
- **프레임 아래로 스크롤하면 텍스트 아웃라인 전문** — 검색·복사 가능해야 인수인계 문서로서 실용성이 생기고 노션 붙여넣기에도 유리
- 워터마크는 우하단 로고 16px + "…로 만들었습니다" 12px `n-400`
- **배너형 CTA 금지** — 공유받은 사람에게 광고로 보이는 순간 공유가 멈춘다

### 이미지 / PDF

내보내기 파이프라인(`html-to-image` + 오프스크린 렌더)에서 자동 적용:
- 그리드 도트 제거, 배경 순수 흰색, 미니맵·컨트롤·선택 링 제거, 렌즈 강제 "흐름+사람"
- **노드 그림자 제거, 보더 1.5px로 남김** (슬라이드 위에서 그림자는 지저분하다)
- **타이틀 블록 자동 삽입**: 제목 28px/600 + 한 줄 설명 15px `n-500` + 우측 작성자·최종수정일 + 요약 칩 3개(`12단계` `담당 4명` `총 약 6시간`)
- **하단 푸터**: 범례(타입 3종 + 인계 마커) 12px + 워터마크. *이 워터마크가 사내 확산의 실질적 유통 경로다*
- PNG: pixelRatio 2, 여백 48px. 폭 4000px 초과 시 그룹 경계에서 분할
- PDF: A4 세로, 그룹 단위 page-break, 헤더에 제목+`3/5`. **마지막 페이지에 노드별 메타 표**(단계·담당자·도구·시간·빈도) 자동 첨부 — 다이어그램에서 의도적으로 숨긴 정보를 문서에서 회수하는 장치. 인수인계 문서의 실질적 가치가 여기서 나온다

### OG 카드 1200×630

전체 그림을 축소해 넣으면 판독 불가. → 좌 480px 텍스트 블록(제목·작성자·단계 수), 우 720px에 **상단 3~4개 노드만 크롭**해서 실물 크기로. "무엇에 대한 문서인가"만 전달하면 된다.
`next/og` 동적 생성, 한글 정적 subset 임베드 필수, `summary_large_image`.
노션 임베드는 `?view=embed`로 상단바 제거.

## 9. 모션

```css
--dur-instant: 80ms;  --dur-fast: 140ms;  --dur-base: 200ms;
--dur-slow: 320ms;    --dur-stagger: 40ms;
--ease-out:      cubic-bezier(.16, 1, .3, 1);
--ease-standard: cubic-bezier(.2, 0, 0, 1);
--ease-flow:     cubic-bezier(.2, .8, .2, 1);   /* 노드 이동 */
```

**쓰는 곳 4개만**
1. **문장 입력 → 노드 생성** — `opacity 0→1 + translateY(4px)`, 140ms, 40ms 스태거. **이게 이 제품의 "마법의 순간"이므로 여기만 공들인다**
2. 엣지 연결 — `stroke-dashoffset` 320ms, 1회
3. 메타데이터 카드 스택 — 수평 슬라이드 200ms
4. 패널/시트 전환 — 200ms

재레이아웃으로 기존 노드가 움직일 때는 위치를 점프시키지 말고 `transform 220ms var(--ease-flow)`로 흐르게 한다.

**안 쓰는 곳**: hover 스케일, 버튼 눌림 트랜스폼, 스켈레톤 shimmer(정적 회색 블록으로 대체), 숫자 카운트업, **스프링 오버슈트**, 로딩 스피너(텍스트 상태로 대체), confetti.

> **오버슈트가 있는 순간 도구는 장난감이 된다** — 모든 easing은 감쇠형만.

`prefers-reduced-motion: reduce`에서는 duration 전부 0ms, opacity만 유지.
