## 2. 온보딩 질문 연쇄

| 상태 | 명세 |
|---|---|
| **첫 진입** | 전체화면, 질문 28px/700 하나만. 상단 **2px 라인 진행 인디케이터** — 숫자·%를 절대 인쇄하지 않는다. `aria-hidden="true"` 처리하고 스크린리더에는 `<h1>` 안에 "1번째 질문"을 넣는다 |
| **입력 중** | 입력 즉시 `[다음]` 비활성→활성. **비활성 상태에서도 버튼은 보이고 포커스 가능해야 한다** — `disabled` 대신 `aria-disabled="true"` + 클릭 시 인라인 안내. **40~50대 사용자에게 회색 버튼은 "고장난 화면"으로 읽힌다** |
| **건너뛰기** | `[모르겠어요 / 나중에]`를 `[다음]`과 **동일 크기·동일 위계**로. 색만 secondary. 누르면 사과·경고 없이 다음 질문 |
| **뒤로 가기** | 좌상단 `← 앞 질문` 상시 노출 + **브라우저 뒤로가기가 반드시 같은 동작**을 해야 한다. 앞 질문으로 가면 이전 답이 그대로 있고 커서가 문장 끝에 놓인다 |
| **이탈 후 복귀** | 답변은 매 질문 종료 시 IndexedDB + 서버 draft 양쪽 기록. 복귀 시 **모달 금지**, 상단 인라인 바: "적어두신 3단계가 그대로 있어요. 4번째 질문부터 이어서 하시겠어요?" `[이어서]` `[처음부터]` |

## 5. 자동 저장 — 가장 공들일 영역

### 원칙 3개

**(a) 저장 상태는 색만으로 절대 전달하지 않는다** — 항상 텍스트가 있다.
**(b) 실패는 즉시 소리치지 않고 단계적으로 승격한다** — 첫 실패는 대부분 순간적 네트워크 흔들림이고, 즉시 빨간 배너를 띄우면 하루 20번 놀란다.
**(c) 어떤 경우에도 "내용이 사라질 수 있다"는 문장을 쓰지 않는다** — 실제로 로컬에 남아 있으므로 거짓말이 아니다.

```
idle → queued → sending → saved
                    ↘ retrying(1) → retrying(2) → degraded → offline
```

| 상태 | 상단바 표시 | 승격 UI | 문구 |
|---|---|---|---|
| **저장됨** | `저장됨` | 없음 | hover 시 `저장됨 · 오후 3:12` (`<time>`, tabular-nums) |
| **저장 중** | `저장 중` | 없음 | 800ms 안에 끝나면 눈에 거의 안 보인다. 그게 정상 |
| **재시도 중 (≤6s)** | `저장 중` **유지** | 없음 | **사용자에게 알리지 않는다.** 백오프 800ms → 2s → 5s |
| **저장 지연 (6~20s)** | `저장 대기 중` | 상단바 텍스트만 변경 | hover 시 "연결이 느려요. 계속 다시 시도하고 있어요" |
| **저장 실패 (20s+ / 3회)** | `이 기기에 저장됨` | 상단 **고정 인라인 바** — 모달 아님, 편집 차단 안 함. 배경 `n-100`, 좌측 3px `#9E6511`, **빨강 아님** | "지금은 서버에 저장되지 않고 있어요. **작성하신 내용은 이 브라우저에 그대로 남아 있어요.** 연결이 돌아오면 자동으로 올라갑니다." `[지금 다시 시도]` `[내용 복사해두기]` |
| **오프라인** | `오프라인 · 이 기기에 저장됨` | 같은 인라인 바 | "인터넷 연결이 끊겼어요. 계속 작성하셔도 됩니다 — 다시 연결되면 저절로 저장돼요." |
| **재연결** | `저장 중` → `저장됨` | 인라인 바 제거 + 4초 토스트 | "다시 연결됐어요. **그동안 쓰신 내용까지 모두** 저장했어요." — **'모두'가 핵심 단어다** |
| **다른 탭에서 편집 중** | `보기 전용` | 인라인 바 | "이 문서를 다른 탭에서도 열어두셨어요. 내용이 엇갈리지 않도록 이 탭은 보기 전용으로 뒀어요." `[여기서 편집하기]`. `BroadcastChannel('doc:'+docId)` 리더 선출 |
| **revision 충돌** | `합치는 중` → `저장됨` | 대부분 무침묵 병합 | 병합 불가 op만: "다른 곳에서 같은 단계를 고치셨네요. 두 내용을 모두 남겨뒀어요." `[무엇이 달라졌는지 보기]` — **어느 쪽도 버리지 않는다. 자동 선택 금지** |

### 라이브 리전 규칙

```tsx
// 상태 변화만 읽고, 진행 중은 읽지 않는다
<div role="status" aria-live="polite" aria-atomic="true" className="sr-only">
  {announce}   {/* 'saved'|'offline'|'reconnected'|'degraded' 진입 시에만 */}
</div>
<span className="save-indicator" data-state={state}>{label}</span>
```

`sending`을 `aria-live`로 읽으면 타이핑 중 스크린리더가 몇 초마다 "저장 중"을 반복해 **사용이 불가능해진다.** 읽는 것은 `saved`(첫 1회 + 이후 5분에 1회), `degraded`, `offline`, `reconnected` 뿐.

## 8. 로딩 전략 (스피너 없이)

| 구간 | 원칙 | 구현 |
|---|---|---|
| **<100ms** | **아무 상태도 만들지 않는다** — 로딩 표시가 오히려 지연으로 지각됨 | 낙관적 반영 후 조용히 커밋 |
| **100~800ms** | **자리는 잡되 말은 걸지 않는다** | 대상 영역만 정적 회색 블록(`bg n-100`, **transition·shimmer 없음**). 버튼은 라벨 유지 + `aria-busy="true"`, `disabled` 금지(포커스 유실) |
| **800ms~3s** | **텍스트 상태 1줄** | 13px `n-550` "그림을 정리하는 중이에요". `aria-live="polite"` 1회 |
| **3s+** | **서수 단계 + 탈출구** | "2/3 그림 그리기" + `[취소]`. 15s 초과 시 "생각보다 오래 걸리네요. 계속 기다릴게요." |

**낙관적 처리로 로딩을 아예 없애야 하는 곳** (전부 op 기반이라 가능)
아웃라인 타이핑·Enter·삭제·순서 이동, 노드 생성, 갈래 만들기, 담당자/도구/시간 칩 선택, 문서 제목 변경, 체크리스트 체크, 렌즈 전환, 줌·팬, 그룹 접기.

**낙관적으로 하면 안 되는 곳**
공유 링크 발급(서버 토큰), 내보내기, 문서 삭제, 조직 프로세스 조립 확정. **여기서는 실패 시 되돌리는 경험이 더 나쁘다.**

## 9. 에러 바운더리와 복구

**경계 4개**: `AppShell` / `OutlineErrorBoundary` / `CanvasErrorBoundary` / `MetaStackErrorBoundary`.
**아웃라인과 캔버스는 서로 독립**이어야 한다 — 캔버스가 죽어도 글은 계속 쓸 수 있어야 데이터가 안 사라진다.

| 실패 | 처리 |
|---|---|
| **ELK 크래시 / 타임아웃** | 워커라 메인 스레드는 안 죽는다. `Promise.race([elk, timeout(4000)])` → 마지막 성공 좌표 유지 → 3회 연속이면 폴백 세로 스택. 워커 자체가 죽으면 1회 재생성, 그마저 실패 시 **텍스트 목록을 정식 UI로 표시**: "그림 그리기가 잘 안 되네요. 대신 순서대로 보여드릴게요." — 접근성용으로 만든 텍스트 대체본이 여기서 값을 한다 |
| **에디터 상태 손상** | ① `items` 스냅샷을 IndexedDB에 즉시 덤프 ② 에디터만 언마운트→재마운트(`itemToBlock`으로 도메인 모델에서 재구성) ③ "편집기를 새로 열었어요. 내용은 그대로예요." — **도메인 SoT가 `items`이지 ProseMirror JSON이 아니라는 결정이 여기서 값을 한다** |
| **탭 종료 시 미저장** | ① `visibilitychange(hidden)`에서 `sendBeacon` 플러시 — **주 방어선** ② 큐가 비지 않았을 때만 `beforeunload`. **항상 띄우면 안 된다**(무해한 이탈에 매번 경고하면 학습된 무시가 생긴다) ③ IndexedDB 미러 항상 유지 |
| **구형 브라우저** | 하한선 **Chrome/Edge 111+, Safari 16.4+, Firefox 121+** (`:has()`, CSS nesting, `structuredClone`, `BroadcastChannel` 기준). 미만이면 편집기를 열지 않고 읽기 전용으로 유도. **공유 페이지 `/s/[id]`는 하한선을 훨씬 낮게** — RSC 정적 HTML + 서버 렌더 SVG로 JS 없이도 아웃라인 전문 열람 가능. **열람자를 통제할 수 없기 때문이다** |

## 10. 성능 인지 — 지점 5개

| # | 지점 | 목표 | 방법 |
|---|---|---|---|
| 1 | 문서 열기 → 첫 노드 | LCP < 1.2s, 캔버스 첫 페인트 < 600ms | **저장된 레이아웃 좌표 캐시**로 즉시 렌더, ELK는 백그라운드 검증 |
| 2 | 첫 글자 입력 지연 | INP < 100ms | 에디터 아일랜드 **우선 하이드레이트**, 캔버스는 `requestIdleCallback` 이후. **사용자는 오른쪽이 늦게 뜨는 건 용서하지만 왼쪽이 안 먹히는 건 못 참는다** |
| 3 | Enter → 노드 등장 | 140ms 안에 애니메이션 시작, **서버 왕복 0** | 완전 낙관적. `derive()` O(n), 200노드 < 5ms. 구조 diff 게이트로 타이핑의 95%는 ELK를 건너뜀 |
| 4 | 붙여넣기 → 결과 | 200줄 < 300ms(동기), 500줄+ 워커 | 정규식 기반, AI 없음. **300ms 넘는 순간 "붙여넣으면 바로 된다"는 마법이 깨진다** |
| 5 | 렌즈 전환 · 줌 · 팬 | 60fps, 프레임 드랍 0 | 렌즈는 **위치를 1px도 안 바꾸므로 레이아웃 재계산이 없다**(CSS 변수 + opacity만) |

보조 지표: 저장 표시가 `저장 중`에 머무는 중앙값 **< 400ms**. 이 숫자가 커지면 **실제 데이터 손실이 없어도 사용자는 제품을 불신한다.**
