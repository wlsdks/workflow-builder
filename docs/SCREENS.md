## 0. 전 화면 공통 규약

**토큰 별칭** (이하 축약)
`ink #1C1B19` · `sub #6F6A62` · `ph #6F6A62` · `bd #E4E1DB` · `bd-2 #948F87` · `cv #F7F6F3` · `app #FCFBF9` · `br #1F5C46` · `br-f #2A7358` · `br-50 #EEF6F1` · `n-100 #F0EEEA` · `warn #9E6511` · `hold #6E4666` · `danger #B4342B`

**포커스 링 (전역 단일 규칙)** — 이중 링으로 어두운 배경에서도 3:1 보장
```css
box-shadow: 0 0 0 2px var(--n-25), 0 0 0 4px var(--brand-500);
```
`ring-offset` 이중 링 금지. 버튼·칩·카드·노드 전부 동일. `:focus-visible`만, 마우스 클릭엔 링 없음.

**밀도 2단계**

| 경로 | 컨트롤 | 본문 | 화면 |
|---|---|---|---|
| 작성 | 44px | 16px | 온보딩(2), 카드 스택(4) |
| 반복 사용 | 32/36px | 15px | 홈(1), 에디터(3), 요약(5), 체크리스트(7), 공유(6) |

**상시 노출 잠금 신호** — 홈·에디터·카드 스택·요약·체크리스트 상단바 좌측에 항상 `🔒 나만 보기`
(자물쇠 14px `ink` + 13px/500 `sub`, h24, padding 0 8px, radius 999, bg `n-100`)
클릭 시 240px 팝오버: *"이 문서는 나와 내가 만든 링크를 가진 사람만 볼 수 있어요. 관리자도 볼 수 없습니다."*

**조회자 아바타 스택·사용자 아바타·조회 로그 UI는 어떤 화면에도 없다.**

**모션** — 진입 `opacity 0→1 + translateY(4px)` 140ms `--ease-out`. 패널·시트 200ms. 스피너·shimmer·카운트업 금지.

### 카드 내부

- 폭 352 / 높이 152 / radius 12 / bg `#FFFFFF` / border 1px `bd` / `--edge-flat` inset. **그림자 없음**
- padding `18px 20px 16px 20px`
- **좌측 미니 스파인**: 카드 좌 20px 지점, 세로 3px 폭, 높이 56px. 노드 개수만큼 2px 세그먼트 + 4px gap, 색 `bd-2`. 분기 세그먼트만 `warn`, 기다림은 `hold`
  → **다이어그램 썸네일 이미지를 쓰지 않는다.** 축소하면 판독 불가이고 렌더 비용이 크다

- 메타 라인: 하단 고정 44px 지점. `12단계 · 담당 3명` 12/1.5/500 `sub`, tabular-nums

### 인터랙션

- 카드 **hover**: `border-color: bd-2`, 140ms. 스케일·리프트 없음
- 카드 **클릭**: 전체 카드가 링크(`<a>` 래핑)
- **카드에 `•••` 메뉴를 두지 않는다.** 삭제·복제는 에디터 내부에서만 — **목록에서 실수로 지우는 경로를 만들지 않는다**
- **키보드**: Tab = 새 흐름 → ••• → 검색 → 정렬 → 카드 1..n. 그리드 안에서는 ←→↑↓ (roving tabindex). Enter 열기. `/` 검색 포커스, `n` 새 흐름
- **정렬**: 최근 수정 / 이름 / 단계 많은 순. **"완성도 순" 정렬은 만들지 않는다** — 평가로 읽힌다

### 반응형

| 폭 | 처리 |
|---|---|
| ≥1024 | 3열 그리드, 콘텐츠 1120px |
| 768~1024 | 2열, 카드 폭 유동(minmax 320px) |
| <768 | 1열. 카드 높이 152→112px (미니 스파인 가로 배치, 제목 1줄). 검색 sticky, 정렬은 아이콘 + 바텀시트 |

### 접근성

- `role="list"` / `role="listitem"` + `<a aria-label="견적서 발행, 12단계, 3일 전 수정">`
- 검색 `role="searchbox"`, 결과 개수를 `aria-live="polite"`로 "3개 찾았어요"
- 잠금 칩 `<button aria-expanded>` + 팝오버 `role="dialog"`, 포커스 트랩, Esc 닫기
- 빈 상태 헤드라인은 `<h1>`. 고스트 노드는 `aria-hidden="true"`

## 2. 온보딩 `/workflows/new`

### 진행 인디케이터

점·숫자·"3/6" 표기를 쓰지 않는다. 뷰포트 상단 **높이 2px 라인**(`fixed; top:0`), 트랙 `bd`, 채움 `br`, `width` 320ms `--ease-out`.

**총 단계 수를 모르는 구간(질문 연쇄)에서는 점근 채움** — 답변 1개마다 남은 거리의 40%를 채워 100%에 닿지 않게 한다. *"몇 개 더 남았지?"라는 압박을 만들지 않기 위함이다.*

### 공통 프레임

```

  ← 콘텐츠 640px 중앙 · 상단 라인에서 첫 요소까지 168px (뷰포트<720이면 96px) →

  ┌─────────────────────────────────────────────────────────┐
  │ 어느 팀에서 일하세요?                 28/1.32/700/-.025em │
  │                                       ↕ 10px             │
  │ 나중에 바꿀 수 있어요.                 15/1.65/400 sub    │
```

**칩 스펙** — h40 / padding 0 18 / r999 / 1px `bd-2` / bg `#FFF` / 15px/500.
hover `border bd-2`. **선택**: bg `br-50` / border 1.5px `br` / 텍스트 `br` / weight 600.
**체크 아이콘 없음** — 색+굵기+테두리 3중 인코딩으로 충분.

### 3단계 흐름

**Step 1 — 부서** (단일 선택, 선택 즉시 [다음] 활성화). "직접 입력"은 칩 자리가 h44 인풋으로 인플레이스 치환.

**Step 2 — 업무명**
h44 인풋 + 아래 **부서별 추천 칩 6개**. 칩 클릭 = 인풋 채움 + 300ms 후 자동 진행(취소 가능: 하단 "되돌리기" 3초 노출).

**Step 3 — 질문 연쇄**

```
  그다음엔요?                                    28px
                                     ↕ 24px
  ┌──────────────────────────────────────────────────┐
  │ 영업팀에서 요청 메일을 받는다                     │  h44→auto
  └──────────────────────────────────────────────────┘  1.5px br-f
                                     ↕ 12px
  지금까지 적은 것                                  12px sub
  1  담당자에게 견적 요청이 온다              [수정]  h36, hover만 노출
  2  ERP에서 단가표를 연다                    [수정]
                                     ↕ 28px
  [  다음  ]   [ 여기까지예요 ]      44px / 44px 동등 크기
```

- 답변 목록은 최근 3개만, 4개 이상이면 상단에 "…앞의 2개" 토글
- **Enter = 다음 질문.** IME 대응: `compositionend` 이후에만 커밋으로 해석, `isComposing === true`인 keydown은 무시
- **3번째 답변이 들어간 순간** 우하단에 **240×160px 미니 프리뷰**가 200ms 페이드로 등장하며 노드가 40ms 스태거로 그려진다 → **마법의 순간**
- 4번째 답변에서 프리뷰 상단에 12px `sub` "그림이 커지고 있어요" 3초
- "여기까지예요" → **라우팅이 아니라 레이아웃 확장 애니메이션 320ms**: 미니 프리뷰가 우측 캔버스 위치·크기로 커지고, 답변 목록이 좌측 아웃라인으로 미끄러진다. **새 화면이 아니라 "같은 문서가 펼쳐진 것"으로 지각시킨다**

### 상태

| 상태 | 표현 |
|---|---|
| 초기 | [다음] disabled (bg `n-100`, 텍스트 `sub`, cursor default) — 단, `aria-disabled`로 포커스는 유지 |
| 빈 채로 다음 | **이동을 차단하지 않는다.** 빈 Enter는 무시하고 shake 없이 placeholder만 140ms 강조 |
| 저장 실패 | 하단 h36 인라인 13px "아직 저장되지 않았어요. 계속 적으셔도 돼요 — 연결되면 자동으로 저장됩니다." **모달 금지** |
| 이탈 시도 | 답변 2개 이상일 때만 `beforeunload`. **1개 이하는 붙잡지 않는다** |

### 반응형 / 접근성

- 768~1024: 콘텐츠 560px, 상단 여백 120px, 미니 프리뷰 200×132
- <768: 콘텐츠 100%−32px, 상단 64px, **질문 24px로 축소**(28px는 2줄이 되어 리듬이 깨짐). **미니 프리뷰 제거**, 하단 고정 바 48px에 "지금까지 4단계 · 그림 보기" → 바텀시트
- 각 단계 `role="group" aria-labelledby={질문id}`. 전환 시 질문 `<h1>`에 `tabIndex={-1}` + `.focus()`
- 진행 라인 `role="progressbar" aria-valuetext="6단계 중 3번째 질문"` — **시각적으로는 숫자를 안 쓰되 보조기술에는 제공**
- **키보드 트랩 없음** — 온보딩은 모달이 아니라 페이지다. Esc는 아무 동작 없음(오작동 이탈 방지)

### 아웃라인 블록

한 블록 = 한 단계. **필드 라벨 인쇄 금지.**

```
 ⠿  견적 요청이 들어온다                              😤
 ↑   ↑                                                ↑
 드래그핸들 16px       본문 15/1.65/400 ink        짜증 토글 16px
 blk 좌측 -24px                                    상시 노출
 hover 시에만 opacity 0→1 (단, 커서 있는 줄은 항상 표시)
```

- 블록 padding `10px 0`, 블록 간 gap 4px, 갈래 간 24px
- **도구 자동 추출 배지**: 문장에 "엑셀"이 들어가면 줄 끝에 `Excel?` 배지(h20/r4/1px `bd`/11px `sub`) → 클릭 = 확정, X = 무시. **입력이 아니라 확인**
- 하단 상시 노출 버튼 3개: h36 / r6 / 1px `bd-2` / bg `#FFF` / 14px/500 —
  `+ 다음 단계` `◇ 갈래 만들기` `⏸ 기다리는 시간`

### 분기 컨테이너 — 정확한 구조

- Tab/Shift+Tab은 "갈래 안으로/밖으로"의 **가속기로만** 동작. 유일 통로 아님

### 리사이즈 · 선택 동기화

- 핸들: 시각 1px `bd`, 히트 8px(터치 24px). 드래그 중에만 2px + `br-f`. 스냅 360/440/560px(±12px 자석). `localStorage: outline.width`
- **키보드 리사이즈**: 핸들 포커스 후 ←→ 8px, Shift+←→ 40px. `role="separator" aria-valuenow aria-valuetext`
- **캔버스는 v1에서 읽기 전용.** 아웃라인 블록 포커스 ↔ 노드 selected 양방향 동기화(노드 클릭 → 해당 블록 캐럿 + `scrollIntoView({block:'center'})`)
- 노드 hover 150ms → 240px 팝오버. 노드 클릭 → 우측 360px 인스펙터가 **캔버스 위에 오버레이**(캔버스는 1px도 안 움직인다)
- **타이핑 중 재배치 금지.** 트리거는 Enter/삭제/분기 생성·삭제/순서 이동/blur만

### 상태 / 반응형 / 접근성

- **초심자 배려**: 단계 3개 이하면 우측 캔버스 대신 우하단 240px 미니 프리뷰 + 캔버스 영역은 `cv` 단색. **4번째 단계에서 2패널로 확장(320ms)**
- ≥1024 2패널 / 768~1024 상단 세그먼트 컨트롤 / <768 §10
- Tab 순서: 잠금칩 → 제목 → 공유 → ••• → 아웃라인 블록 → 하단 버튼 3개 → 리사이저 → 캔버스(단일 tabstop, 내부 roving)
- **인스펙터는 포커스를 트랩하지 않는다**(사이드 패널이지 모달이 아님) — Esc로 닫고 원래 노드로 복귀
- 캔버스 접근성은 [ACCESSIBILITY.md §2](./ACCESSIBILITY.md) 참조 — **아웃라인 텍스트가 정본**

```
    ☐  견적서 PDF 발송                        bg #FCFBF9 1px bd r12
    ☐  ERP에 발행 기록
```

- 활성 카드만 88px로 펼쳐지고 나머지 미완료는 56px 접힘. **한 번에 하나만 주목**
- **"바뀌었어요"** → 그 자리에서 인라인 편집(h44), 저장 시 원본 노드가 갱신되고 `last_confirmed_at` 갱신
- **"이제 안 해요"** → 단계 삭제 확인(`danger` 버튼은 여기와 문서 삭제에만)
- 완료 스트립 클릭 → 다시 펼쳐짐(체크 해제 가능)
- 전부 완료: 15px "12단계 다 하셨어요." + `[ 문서로 돌아가기 ]`. **confetti·축하 애니메이션 절대 금지**

**상태** — 중단 후 재진입: 진행 상태는 `sessionStorage`로 유지하되 **24시간 후 초기화**(다음 달 마감은 새로 시작해야 한다) + "이어서 하시겠어요? [처음부터]"

**반응형** — **<768에서 이 화면이 가장 잘 동작해야 한다.** 콘텐츠 100%−16px, 활성 카드 padding 16, `[했어요]` h48 폭 100%, **엄지 도달 범위를 위해 카드 하단 정렬**

**접근성** — `<ul role="list">`, 각 항목 **실제 `<input type="checkbox">`**(가짜 div 금지). 활성 항목 `aria-current="step"`. 체크 시 `aria-live="polite"` "5개 중 4개 했어요, 다음은 내부 승인 요청 메일 보내기". Space=체크, ↑↓=이동

## 9. 첫 60초 시나리오

**0–5초 — 판단이 끝나는 구간.**
사용자는 인사팀 슬랙 공지의 링크를 눌러 들어왔다. 로그인은 SSO로 통과되어 있다. 화면에 뜨는 것은 로고도 튜토리얼도 아니라 **560px 폭의 조용한 빈 화면**이다. 상단바에 `🔒 나만 보기`가 이미 켜져 있고, 중앙에는 점선 노드 3개가 위에서 아래로 점점 옅어지며 놓여 있다. 그 아래 28px 굵은 문장 하나 — *"요즘 반복해서 하는 일, 하나만 적어볼까요?"*

파란 헤더 바도, 결재선도, 부서 트리도, 진행률 링도 없다. **이 5초에 "회사가 시킨 시스템"이 아니라 "빈 노트"라는 판정이 내려진다.** 화면 맨 아래 한 줄이 이 판정을 봉인한다: *"적은 내용은 나만 볼 수 있어요."*

**5–20초 — 첫 입력까지.**
`[흐름 적어보기]`를 누른다(44px 잉크 버튼, 그림자 없이 inset 하이라이트만). 화면 상단에 2px 라인이 나타나 왼쪽에서 약 15%를 채운다 — 숫자도 점도 없다. 질문: *"어느 팀에서 일하세요?"* 칩 10개. `재무·회계`를 누르면 칩이 딥 에버그린 테두리로 바뀌고, 다음 질문이 200ms 슬라이드로 들어온다. *"요즘 반복해서 하는 일, 뭐가 제일 자주 있나요?"* 인풋 아래에 재무팀 추천 칩 6개가 이미 놓여 있다 — `월 마감 정산`. 누른다.

**여기까지 타이핑 0회.** 20초 지점에서 사용자는 아직 한 글자도 안 썼는데 문서가 시작되어 있다. **입력 절벽을 넘기는 지점이 여기다.**

**20–60초 — 마법의 순간.**
*"가장 먼저 무슨 일이 시작되나요?"* 처음으로 자판을 친다. "각 팀에서 카드값 정산서를 메일로 받는다." Enter. 질문이 *"그다음엔요?"* 로 바뀌고, 방금 쓴 문장이 아래 목록에 `1`번으로 조용히 쌓인다.

**세 번째 Enter 직후**, 우하단에 240×160px 프레임이 페이드인하며 노드 3개가 40ms 간격으로 위에서 아래로 그려진다 — `opacity 0→1 + translateY(4px)`, 140ms. 스파클도 "AI가 분석 중…" 펄스도 없다. **그냥 자기가 쓴 문장이 카드가 되어 선으로 이어진다.**

네 번째 답변을 넣으면 프레임 위에 12px 회색 한 줄이 3초간 뜬다: *"그림이 커지고 있어요."*

60초 지점에서 사용자는 4~5단계를 적었고, 자기 손으로 만든 그림 하나를 이미 보고 있으며, **아직 "업무명" "소요시간" 같은 필드 라벨을 한 번도 본 적이 없다.** 메타데이터 질문은 시작조차 하지 않았다 — 그건 다 쓰고 난 뒤의 일이다.

## 10. 모바일 전략 (<768px)

현장·물류·생산 직원은 데스크톱을 안 쓴다. **이 제품의 커버리지 절반이 여기 걸려 있다.**

### 버리는 것

- **2패널 동시 표시** — 좌우 분할은 <768에서 어느 쪽도 못 쓰게 만든다
- **캔버스 상시 노출** — 다이어그램은 요청해야 나오는 바텀시트로 강등
- **드래그 핸들 순서 변경** — 터치 드래그는 스크롤과 충돌 → 블록 롱프레스(400ms) → 하단 시트에 `위로 / 아래로 / 삭제`
- **hover 팝오버 전량** — 노드 메타, 도구 배지 툴팁, 엣지 근거 설명 → 탭 시 하단 시트
- **리사이즈, 미니맵, 렌즈 전환, semantic zoom 상단 3단계**
- **인스펙터 360px 패널** → 전체폭 바텀시트 max-height 72vh

### 남기는 것 (우선순위 순)

1. **온보딩 질문 연쇄 전량** — **모바일의 주력 경로다.** 질문 24px, 인풋 h48, 하단 고정 액션바 64px(`safe-area-inset-bottom` 반영). 답변 목록은 인풋 위 최근 2개만
2. **아웃라인 편집** — 에디터는 모바일에서 **아웃라인 단독 화면**이 된다. 블록 최소 48px, 하단 고정 툴바 56px에 3버튼 균등 분할. **분기 컨테이너는 좌측 레일 8→6px, 내부 padding 24→16px로만 축소하고 구조는 그대로 유지** — 여기서 구조를 바꾸면 데스크톱과 멘탈 모델이 갈라진다
3. **체크리스트 모드** — **오히려 모바일이 주 무대다**(창고에서 폰 들고 확인)
4. **공유 페이지 열람** — 링크를 받는 사람의 상당수가 모바일
5. **카드 스택** — 한 화면 한 질문 구조라 모바일에 자연 적합
6. **다이어그램 미리보기** — 하단 고정 바 48px에 `지금까지 6단계 · 그림 보기` → 바텀시트 72vh, 핀치 줌 허용, 편집 불가

### 모바일 전용 규칙

- 터치 타깃 최소 44×44px. 12px 캡션에 달린 액션은 전부 h44 래퍼로 감싼다
- **한국어 IME 조합 중 입력값 커밋 금지** — 모바일 키보드에서 특히 파손이 잦다. `compositionend` 전에는 자동 저장 큐에도 넣지 않는다
- 키보드가 올라오면 하단 고정 액션바는 `visualViewport` 기준으로 키보드 위에 붙인다. **버튼이 키보드에 가리면 작성이 중단된다**
- 자동 저장 800ms 디바운스 + `visibilitychange`에 `sendBeacon`. **모바일은 앱 전환으로 세션이 끊기는 일이 상시다**
- **오프라인 허용**: 네트워크가 끊겨도 입력은 계속되고 하단에 12px "아직 저장 안 됨 — 연결되면 자동으로 올라가요". **차단 모달 금지. 창고·현장은 신호가 나쁘다**
