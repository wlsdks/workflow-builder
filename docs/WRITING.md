# UX 라이팅 가이드

> 최종 갱신: 2026-08-17 · 상태: v1.0
> **이 문서는 UI에 노출되는 모든 문구의 최종 권한을 갖는다.** 다른 기획 문서가 쓰는 내부 용어(프로세스, 워크플로, 메타데이터)는 설계 논의용이며 화면에 그대로 나가면 안 된다.

---

## 0. 단 하나의 원칙

**모든 문장은 "이 사람이 나를 재고 있나?"라는 무의식적 질문에 '아니다'라고 답하게 만들어야 한다.**

카피가 예뻐지는 것보다 사용자가 방어를 풀고 사실대로 적는 것이 100배 중요하다.
**아름다운 문장과 안전한 문장이 충돌하면 안전한 문장을 택한다.**

## 1. 보이스

### 화자는 누구인가

**옆자리에 앉은, 일 정리를 유난히 잘하는 동료.**

| 아닌 것 | 왜 |
|---|---|
| **도구** | 도구는 "저장되었습니다"라고 말한다. 동료는 "적은 대로 있어요"라고 말한다 |
| **비서** | 비서는 사용자를 윗사람으로 둔다("무엇을 도와드릴까요?"). **위아래가 생기면 사용자는 "그럼 위에는 누가 있지?"를 떠올린다** |
| **코치** | 코치는 평가한다. 이 제품에서 평가는 곧 죽음이다 |

1인칭 "저"는 최대한 드물게, 주로 사과할 때만("제가 못 읽었어요"). 사용자는 이름+"님" 또는 주어 생략.

**"당신"은 제품 전체에서 딱 한 곳에만 등장한다** — 분석 결과 첫 줄 `당신이 안 해도 되는 일 3가지`. 그 순간만은 약속이 개인 앞으로 정면으로 향해야 한다.

### 형용사 5개와 반례

| 형용사 | 이런 문장 | 이건 아니다 |
|---|---|---|
| **담백한** | "방금 저장했어요." | "오늘도 열심히 기록해주셨네요, 감사합니다" |
| **구체적인** | "그 다음엔 무슨 일이 있나요?" | "업무 프로세스를 체계적으로 정리해보세요" |
| **지시하지 않는** | "순서가 틀려도 나중에 옮길 수 있어요." | "이 단계는 더 잘게 나누시는 것을 권장합니다" |
| **판단하지 않는** | "단계 12개, 도구 4개." | "단계가 12개나 되네요. 복잡한 편이에요" |
| **되돌릴 수 있는** | "지울까요? 30일 안엔 되돌릴 수 있어요." | "정말 삭제하시겠습니까? 복구할 수 없습니다" |

### 문체 규칙 (예외 없음)

- **해요체 고정.** 하십시오체는 버튼·안내에서 금지. 합니다체는 인사팀 공지문·약관에서만
- **한 문장 25자 이내.** 한 덩어리에 두 문장까지. 세 문장이 필요하면 화면을 나눈다
- **버튼 라벨 2~7자, 동사로 끝난다.** "확인" 같은 무의미어 대신 실제로 하는 일을 쓴다
- **감탄사 전면 금지.** "와", "좋아요", "훌륭해요", "짠"
- **느낌표 제품 전체에 0개.** 알림·이메일·공지문 포함
- **이모지 0개.** 물음표는 실제 질문에만
- **말줄임표 금지.** "잠시만요…" 대신 "10초쯤 걸려요."

## 3. 용어 확정표

**판단 기준**: ① 한국 사무실에서 이미 소리 내어 쓰는 말인가 ② 한국어로 바꿨을 때 의미가 더 선명해지는가. **②가 우선한다.**

| 원어 | 확정 표기 | 판단 |
|---|---|---|
| workflow | **흐름** (문서 단위는 "업무 흐름") | "워크플로우"는 비개발자에게 IT 프로젝트 냄새 |
| step | **단계** | 이미 일상어 |
| branch | **갈래** | "분기"는 회계 분기와 충돌하고 딱딱하다 |
| handoff | **인계** / 동사 "넘기다" | "핸드오프"는 정착 안 됨 |
| diagram | **그림** (UI 라벨) / "흐름도"는 부제에만 | "다이어그램"은 사용자를 긴장시킨다 |
| checklist | **체크리스트** 유지 | 이미 사무직 일상어 |
| template | **예시** ("예시로 시작하기") | "템플릿"은 채워야 할 양식의 압박 |
| export | **내보내기** | |
| archive | **보관함** | |
| dashboard | 직원 **모아보기** / 관리자 화면만 "대시보드" | |
| backlog | **백로그** — 경영진 화면 한정 | 직원 화면 등장 금지 |
| metadata | 화면에 쓰지 않음. **"누가·뭘로·얼마나"** | 내부 용어 |
| exception | **예외** | 이미 일상어 |
| lead time / SLA | **기다리는 시간** | 관리 어휘 제거 |
| owner / assignee | **"이 단계 하는 사람"** / 카드 라벨만 "담당자" | "담당자 배정"은 결재 냄새 |

| parse | **"읽어서 나누기"** | |
| sync | **"올라가요"** | "동기화" 금지 |
| onboarding | **"처음 오신 분 안내"** | |
| automation | 직원 화면 **등장 금지** / 경영진 화면 허용 | 제품 생존 조건 |

## 4. 온보딩

### 시작 화면
- 제목: `하시는 일을 순서대로만 적어주세요.`
- 부제: `잘 쓴 글일 필요 없어요. 나중에 누가 이 일을 이어받아도 헤매지 않게 하는 게 전부예요.`
- 보조: `5분쯤 걸려요. 중간에 나가도 적은 건 남아요.`
- 버튼: `[시작하기]` `[이미 써둔 게 있어요]`

### 부서 선택
- 질문: `어느 팀에서 일하세요?`
- 칩: `영업` `인사` `재무` `마케팅` `고객지원` `총무` `물류` `여러 팀 일을 같이 해요` `여기 없어요`
- 헬퍼: `팀 이름은 나중에 바꿔도 돼요.`

### 업무명
- 질문: `이 중에 제일 자주 하는 일이 있어요?`
- 헬퍼: `하나만 고르면 돼요. 나머지는 나중에 얼마든지 추가할 수 있어요.`
- 마지막 칩 `여기 없는 일이에요` → placeholder `평소에 부르는 이름 그대로 적어주세요`

### 질문 연쇄 — 첫 질문 3안과 판단

| | 문구 |
|---|---|
| A (결과 기점) | `이 일은 뭐가 끝나면 '됐다'인가요?` |
| **B (시작 기점) ★** | `이 일은 보통 어떻게 시작돼요? 누가 뭐라고 하면서 시작되는지만 알려주세요.` |
| C (기억 기점) | `가장 최근에 이 일을 하신 게 언제예요? 그때 제일 먼저 한 일이 뭐였어요?` |

**B안 채택.** A안은 추상적이라 답하려면 자기 일을 요약해야 하는데, **요약은 곧 자기 평가라서 방어를 부른다.** C안은 기억의 정확도를 압박한다. B안은 대부분의 사무 업무가 외부 자극(전화·카톡·메일·결재)으로 시작하기 때문에 답이 거의 자동으로 나온다.

그리고 결정적으로 — **첫 문장의 주어가 '나'가 아니라 '요청한 사람'이라서, 사용자가 자기 자신을 서술 대상으로 두지 않아도 된다.** 첫 화면에서 가장 중요한 심리적 안전장치다.

### 나머지 질문 (전 부서 공통)

> 부서별로 질문 자체를 다르게 만들면 (a) 유지보수가 무너지고 (b) 부서 간 흐름을 이어붙일 때 축이 안 맞고 (c) "우리 부서만 다르게 묻네?"라는 의심을 만든다. **개인화는 예시 문장 한 줄로 충분하다.**

- Q2: `그 다음엔 뭘 하세요? 손이 가는 순서대로요.`
- Q3: `그 중에 다른 사람을 기다려야 하는 데가 있어요?`
- Q4: `경우에 따라 달라지는 데가 있어요? 예를 들면 금액이 크거나, 급하거나.`
- Q5: `이 일은 뭐가 되면 끝난 거예요?`
- Q6: `끝나고 나서 따로 남기거나 알려야 하는 게 있어요?`

공통 보조 버튼: `[잘 모르겠어요]` `[해당 없어요]` — **둘 다 다음 버튼과 동일한 크기로.**

### 전환
- `여기까지가 흐름이에요. 그림은 알아서 그려졌어요.`
- `빠진 게 보이면 지금 넣어도 되고, 나중에 넣어도 돼요.`

## 5. 붙여넣기

- 제목: `이미 써둔 게 있으면 그대로 붙여넣으세요.`
- placeholder: `워드 매뉴얼, 카톡으로 받은 인수인계, 메일 — 아무거나요. 형식은 신경 안 쓰셔도 돼요.`
- 헬퍼: `붙여넣은 원문은 지워지지 않아요. 옆에 그대로 둘게요.`
- 처리 중: `읽는 중이에요. 10초쯤 걸려요.`
- 결과: `이렇게 나눠봤어요. 틀린 데는 고치면 돼요.` / `제가 나눈 거라 어색한 데가 있을 거예요. 합치거나 지워주세요.`
- 카드 버튼: `[위와 합치기]` `[여기서 나누기]` `[지우기]`
- 하단: `[이대로 가져오기]` `[처음부터 직접 쓸래요]`
- 토스트: `8단계로 가져왔어요.`

## 6. 에디터

- 첫 단계 placeholder: `예: 영업사원이 카톡으로 견적 요청을 보내요`
- 이후: `그 다음엔 무슨 일이 있나요?`
- 첫 진입 1회 안내: `순서가 틀려도 괜찮아요. 나중에 끌어서 옮길 수 있어요.`

| 버튼 | 툴팁 |
|---|---|
| `다음 단계` | 순서대로 이어지는 일 |
| `갈래 만들기` | 경우에 따라 달라지는 일 |
| `기다리는 시간` | 내가 뭘 하는 게 아니라, 기다리는 구간 |

### 갈래 컨테이너
- `만약 [ ]라면` — placeholder `예: 금액이 500만 원을 넘으면`
- `아니면 [ ]라면` — placeholder `예: 그 밖에 전부`
- `[경우 하나 더]`
- 헬퍼: `경우를 다 못 적어도 돼요. 자주 있는 두 가지만 적어도 충분해요.`

### 기다리는 시간
- `무엇을 기다려요?` placeholder `예: 팀장님 확인`
- `보통 얼마나요?` — `10분 안` `반나절` `하루` `2~3일` `그보다 오래` `그때그때 달라요`
- 헬퍼: **`기다리는 시간은 아무도 잘못한 게 아니에요. 그냥 흐름의 일부예요.`**

### 저장 상태
- 평시 라벨: `14:02에 저장`
- 방금: `방금 저장했어요`

- 상단: `남은 질문 3개` — **퍼센트 절대 금지, 개수만**

| 도구 | `이때 뭘 쓰세요?` | `엑셀` `사내 시스템` `카톡` `메일` `전화` `종이` `직접 적기` **`모르겠어요`** |
| 소요시간 | `한 번 할 때 대략 얼마나 걸려요?` | `5분 안` `30분쯤` `1시간쯤` `반나절` `하루 넘게` **`그때그때 달라요`** |
| 빈도 | `얼마나 자주 있는 일이에요?` | `하루에 여러 번` `하루 한 번` `주 몇 번` `한 달에 몇 번` `분기·연 단위` **`불규칙해요`** |

- "모르겠어요" 헬퍼: `모르는 걸 아는 것도 정보예요. 그대로 남겨둘게요.`
- **소요시간 카드 하단 고정 문구**: `시간은 대충 적어주세요. 정확할 필요 없어요. 누가 얼마나 빨리 하는지 보려는 게 아니에요.`
- 완료: `끝났어요. 이제 한눈에 볼 수 있어요.` `[요약 보기]`

## 10. 공유 · 체크리스트 · 신선도 · 인계

### 공유
- 버튼: `[링크 만들기]` `[인수인계 문서로 내보내기]` `[PDF]` `[그림으로 저장]`
- 권한: `볼 수만 있어요` / `같이 고칠 수 있어요`
- 생성 후: `링크가 만들어졌어요. 받은 사람은 흐름을 볼 수 있어요. 고칠 수는 없어요.`
- 만료: `30일 뒤에 링크가 닫혀요.` `[기간 바꾸기]`
- 내보내기 옵션: `받는 분이 이 일을 처음 보시나요?` → `네, 처음이에요` / `대충은 아세요`
- 처음 선택 시: `그럼 줄임말이랑 시스템 이름에 설명을 붙여서 만들게요.`

### 체크리스트
- 진입: `이 흐름 그대로 오늘 할 일 목록으로 쓸 수 있어요.` `[체크리스트로 열기]`

- 체크 시: **문구 없음.** 조용한 상태 변화만 (칭찬 금지)
- 완료: `여덟 단계 다 지나셨어요. 이번엔 예외가 있었나요?` `[있었어요]` `[없었어요]`
- 있었어요 → `어떤 게 달랐어요?` → `이걸 흐름에 적어둘까요?` `[적어두기]` `[이번만이에요]`

### 신선도 확인
- 배지: `3주 전에 쓰신 흐름이에요.`
- 질문: `이 세 단계, 아직 이대로예요?` `[맞음]` `[바뀜]` `[이제 안 함]`
- 맞음: `확인했어요. 다음엔 두 달 뒤에 여쭤볼게요.`
- 바뀜: `어디가 바뀌었어요? 단계 번호만 알려주셔도 돼요.`
- 이제 안 함: `알겠어요. 보관함으로 옮겼어요. 지우진 않았어요.`

### 핸드오프 조립
- 제안: `이 다음은 김민수 팀장님이 하시죠? 이어지는 부분은 그분이 제일 잘 아실 거예요.`
- 버튼: `[초대하기]` `[제가 아는 내용이에요]` `[다른 사람이에요]`

- 거절 시: `김민수 님이 '제 일이 아니에요'라고 하셨어요. 다른 분을 찾아볼까요?`

## 11. 에러 · 경고

### 원칙 4가지
1. **주어는 항상 시스템.** "잘못 입력하셨어요" → "제가 못 읽었어요"
2. **세 가지를 순서대로**: 무엇이 안 됐는지 → 적은 내용은 안전한지 → 지금 할 수 있는 것 하나
3. **"실패", "오류", "잘못" 세 단어는 절대 쓰지 않는다.** "안 됐어요"로 통일
4. **사과는 한 번, 짧게.** 반복하면 오히려 큰일 난 것처럼 읽힌다. "제 쪽 문제예요" 정도

## 13. 알림 · 이메일 · 슬랙

### 20초 안에 답하게 만드는 규칙

1. **확인할 내용을 메시지 본문에 넣는다.** 링크를 열게 하는 순간 응답률은 1/5이 된다
2. **버튼 최대 3개**
3. **첫 줄에 무엇에 대한 건지 + 걸리는 시간.** "30초면 끝나요"는 정직할 때만
4. **`[알림]`, `[필독]`, "미확인 3건", 이모지, 느낌표 전면 금지.** 사내 알림 특유의 그 톤이 곧 무시 신호다
5. **한 사람에게 같은 종류의 알림은 2주에 한 번을 넘지 않는다**

## 14. 관리자 화면

### 무엇이 다른가

직원 화면은 **2인칭**("적어주세요"), 관리자 화면은 **3인칭 관찰**("이 흐름에서는 견적 번호를 세 번 옮겨 적고 있어요").

관리자 화면에서는 "자동화 후보", "백로그" 같은 단어를 써도 된다. **단, 사람 이름 옆에 붙이지 않는다.**

### 넘지 말아야 할 다섯 개의 선

1. **개인 단위 집계 화면을 만들지 않는다.** 최소 집계 단위는 '흐름'과 '팀'. "박서연 님의 자동화 후보 4건"이라는 문장은 이 제품에 존재하지 않는다
2. **작성 여부를 사람 이름으로 나열하지 않는다.** `미작성자 12명` ✗ → `아직 안 올라온 업무 12가지` ○
3. **체크리스트 실행 기록은 관리자에게 보이지 않는다.** 그리고 그 사실을 관리자 화면에도 적는다: `체크리스트 기록은 작성자 본인만 봐요. 여기선 볼 수 없어요.`
4. **시간을 사람의 속도로 읽는 카피를 쓰지 않는다.** `평균 처리시간` ✗ → `이 단계는 사람마다 10분에서 2시간까지로 적혀 있어요. 방법이 제각각이라는 뜻이에요.` ○
5. **직원 화면 문구를 관리자가 수정할 수 없다.** 설정 화면에 명시: `직원 화면 문구는 바꿀 수 없어요. 모두가 같은 문구를 보고 있다는 게 이 도구가 작동하는 조건이에요.`

### 카피
- 대시보드 제목: `우리 회사가 실제로 일하는 방식`
- 백로그: `손을 덜어낼 수 있는 일 24가지`
- 정렬: `사람 손이 많이 가는 순` (`비효율 높은 순` ✗)
- 카드: `견적 번호 재입력 — 영업 4개 팀 공통 / 합쳐서 주 11시간 / 필요한 것: 사내 시스템 연동` `[백로그에 넣기]`
- **상단 고정 배너**: `이 화면의 숫자는 일에 대한 거예요. 인사 평가에 쓰는 순간, 다음 분기부터 아무도 사실대로 적지 않습니다.`
