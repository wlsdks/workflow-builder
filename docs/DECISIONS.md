# 결정 기록 (ADR)

> 최종 갱신: 2026-08-17

이 프로젝트는 20개 **역할 관점**의 검토(사람 1명 + Claude, [만들어진 방식](../README.md#이-문서들이-어떻게-만들어졌는지))를 거치며 여러 초기 설계를 뒤집었다. **무엇을 정했는지보다 왜 정했는지, 그리고 무엇을 버렸는지가 더 중요하다.** 이 기록이 없으면 6개월 뒤 같은 논쟁을 처음부터 다시 하게 된다.

각 항목의 형식: **결정 · 맥락 · 대안과 기각 사유 · 뒤집는 조건**

"뒤집는 조건"이 핵심이다. 모든 결정은 특정 가정 위에 서 있고, 그 가정이 깨지면 재논의해야 한다. 어떤 신호가 오면 다시 열지 미리 적어둔다.

# 제품

## D-001 🔒 직원용과 경영진용 약속을 분리한다

**결정** — 같은 데이터, 두 개의 제품 표면. 직원에게는 "설명 안 해도 되는 업무 문서", 경영진에게는 "자동화 백로그". **직원 화면에서 '자동화' 단어를 지운다.**

**맥락** — 초기 기획은 "자동화할 곳을 찾아준다"를 모두에게 동일하게 약속했다. PM 검토에서 이 전제가 무너졌다.

> 김대리는 자기 일을 압니다 — 몸으로. 문서로 없을 뿐입니다. 그에게 "당신 일이 뭔지 알아야 합니다"는 문제 제기가 아니라 잔소리입니다.

더 나쁜 건, 직원 입장에서 최종 산출물("당신 업무 중 자동화 가능한 것 랭킹")이 **위협**이라는 점이다. 이건 채택 문제가 아니라 **데이터 품질 오염** 문제다 — 소요시간은 부풀려지고 짜증 플래그는 정치적으로 선택된다.

**대안과 기각**
- ~~단일 메시지로 통일~~ — 어느 쪽으로 통일해도 한쪽을 잃는다. 자동화로 통일하면 직원이 안 쓰고, 문서화로 통일하면 예산이 안 나온다
- ~~자동화 프레임을 유지하되 부드럽게 표현~~ — 완곡어법은 들킨다. 프레임 자체를 바꿔야 한다

**뒤집는 조건** — 파일럿에서 직원들이 자동화 프레임에 저항하지 않는다는 증거가 나오면(짜증 플래그 사용률이 높고 소요시간 분산이 낮으면) 통합을 재검토한다.

## D-002 🔒 관리자에게 개인 데이터를 보여주지 않는다

**결정** — 관리자 뷰는 **프로세스 단위 집계만**. 5인 미만 그룹은 표시 자체를 차단. 개인 식별자로 드릴다운하는 API를 만들지 않는다. **정책이 아니라 DB 뷰로 강제한다.**

**맥락** — PM과 조직 도입 전문가가 표면적으로 충돌했다. PM은 "자발적 채택은 불가능(확신도 70%), 관리자 대시보드를 앞당겨라", 조직 전문가는 "관리자 대시보드가 첫 릴리즈에 있는 것 자체가 실패 패턴".

실제로는 **"보여주느냐"가 아니라 "무엇을 보여주느냐"에서 갈렸다.** 프로세스 단위 집계는 이르게, 사람 단위는 영원히 — 이 선으로 봉합했다.

조직 전문가의 분석이 결정적이었다:
> 보여주면 초기 3개월은 부서장 압박으로 작성률이 오릅니다. 그 다음 데이터가 방어적으로 왜곡됩니다. 자동화 후보 목록이 쓰레기가 되고, 프로젝트는 6~9개월 뒤 조용히 죽습니다. **되돌리기 불가능합니다 — 한 번 감시 도구로 낙인찍히면 정책을 바꿔도 신뢰는 안 돌아옵니다.**

**대안과 기각**
- ~~부서장에게 팀원 문서 열람권~~ — 위 이유로 기각
- ~~옵트인 방식(직원이 허용하면 관리자가 봄)~~ — 조직에서 "옵트인"은 실질적 강제가 된다. 안 켜면 왜 안 켰냐는 질문이 온다
- ~~애플리케이션 레벨 권한 검사~~ — 언젠가 우회된다. DB 뷰로 내린다

**뒤집는 조건** — **없다.** 이 결정은 뒤집지 않는다. 경영진 요구는 6개월 안에 반드시 오고, 그때 거절하기 위해 이 문서가 존재한다. 자세한 근거는 [TRUST.md](./TRUST.md).

## D-003 ✅ 첫 입력 표면은 아웃라인이 아니다

**결정** — 붙여넣기 파싱 → 질문 연쇄(5~6문항) → 그다음 아웃라인+다이어그램. **아웃라인은 편집기로 강등.**

**맥락** — 초기 기획의 핵심 베팅이 "아웃라인 우선"이었다. UX 검토에서 반박:

> 사람은 자기 업무를 순서가 매겨진 계층 구조로 기억하지 않습니다. 에피소드와 사건으로 기억합니다. 아웃라인은 이 원재료를 **정리한 결과물**인데, 첫 화면부터 정리된 형태를 요구하면 기억 인출과 구조 설계를 동시에 시키는 셈입니다.

그리고 PM·조직·UX 세 명이 **독립적으로** 붙여넣기 파싱을 지목했다. "기존 자산 재활용이 백지에서 쓰게 하는 것보다 압도적으로 전환율이 높다."

**대안과 기각**
- ~~질문 연쇄를 최종 UI로~~ — 느리고 수정이 번거롭다. 온보딩 전용으로만
- ~~빈 아웃라인 + 좋은 플레이스홀더~~ — 플레이스홀더는 백지 공포를 못 없앤다

**뒤집는 조건** — 온보딩 완료율이 60%를 넘고, 그중 질문 연쇄를 건너뛰고 바로 아웃라인으로 가는 비율이 40% 이상이면 순서를 재검토한다.

## D-004 🔒 Tab 들여쓰기를 분기 문법에서 제거한다

**결정** — 분기는 "만약 [ ]라면 / 아니면 [ ]라면" 자연어 껍데기가 인쇄된 **컨테이너 블록**. Tab/Shift+Tab은 동일 동작의 가속기로만 유지.

**맥락** — 이건 개발자의 직관이었다. UX 검토:

> 즉시 이해하지 못할 사용자는 전 직원의 **30~50%**. 더 나쁜 건 **실패 모드가 조용하다**는 점입니다 — Tab을 안 눌러 갈래가 형제 단계로 들어가도 화면은 멀쩡히 그려집니다. 사용자는 자기가 틀렸다는 걸 모르고, 나중에 다이어그램을 보고 "이 도구 이상하다"고 결론냅니다.

**조용한 실패**가 기각의 결정적 이유다. 시끄러운 실패는 고칠 수 있지만 조용한 실패는 신뢰를 갉아먹는다.

**대안과 기각**
- ~~Tab 유지 + 튜토리얼~~ — 튜토리얼은 안 읽힌다
- ~~Tab 유지 + 시각적 들여쓰기 강조~~ — 이해 못 하는 사람에겐 강조해도 이해가 안 된다

**뒤집는 조건** — 없다. 컨테이너 블록이 Tab의 상위 호환이다.

## D-005 ✅ 노드 타입 3개, 표현력은 속성으로 확장

**결정** — `작업` / `분기` / `기다림`. 타입은 안 늘리고 속성으로 흡수한다.

| 타입 | 속성 | 커버 |
|---|---|---|
| 작업 | 반려율, 반송 대상 | 재작업 루프 |
| 분기 | `mode: 택1/동시/조건스킵` | **AND/XOR 구분** |
| 기다림 | `waitFor: 승인/응답/시각/자원` + 타임아웃 | 승인 루프, 에스컬레이션 |

**맥락** — 3명이 다르게 주장했다. PM은 3번째 타입을 "승인", 다이어그램 디자이너는 "대기", BPM 전문가는 대기의 4종 세분화.

BPM 검토가 문제의 크기를 알려줬다 — 규칙 4개로는 단계 수 기준 60~70%지만 **자동화 가치 기준으로는 훨씬 낮다. 못 그리는 영역에 돈이 몰려 있기 때문이다.** 특히 AND/XOR 미구분은 병렬 구간을 순차로 합산해 **리드타임을 과대 계산**한다 — 시각화가 아니라 **숫자가 틀린다.**

`기다림` 하나 + `waitFor` 속성이 셋을 모두 만족한다. 사용자에겐 "기다림" 하나만 보이고, 고르면 "무엇을 기다리나요?"로 자연스럽게 갈라진다. 커버리지 55~65% → **85%**, 신규 심볼 학습 0.

**대안과 기각**
- ~~타입 4~5개로 확장~~ — 비개발자에게 팔레트를 주면 그 자체가 진입장벽
- ~~`/연결` 텍스트 명령으로 예외 처리~~ — "비개발자 제품에서 escape hatch가 문법이면 그 기능은 안 쓰이거나 파워유저 전용이 된다"

**뒤집는 조건** — 파일럿 문서의 30% 이상이 `기다림`의 `waitFor`를 "승인"으로만 쓰면, 승인을 독립 타입으로 승격 재검토.

## D-006 ✅ 갈래 합류는 기본값 합류 + 상시 노출 2택

**결정** — 갈래 컨테이너 하단에 항상 보이는 칩 `○ 이어짐 / ● 여기서 끝`. 기본은 이어짐.

**맥락** — PM은 "기본을 종료로" 주장했다. 반품·반려·이탈 갈래는 합류하지 않기 때문이다.
> 기본값을 합류로 두면 사용자가 매번 제품과 싸웁니다.

하지만 승인/반려가 `기다림` 타입으로 분리되면(D-005) 순수 분기는 합류가 더 흔하다. 실무 예: "단순 문의 → 즉시 답변 / 복잡 → 팀장 문의 후 답변" → 둘 다 "CRM 기록"으로 합류.

**핵심은 기본값이 아니라 가시성이다.** 기본값이 틀렸을 때 한 번의 클릭으로 고칠 수 있고 그 컨트롤이 눈에 보이면, 어느 쪽을 기본으로 하든 사용자가 싸우지 않는다.

**뒤집는 조건** — 파일럿에서 "여기서 끝"으로 바꾸는 비율이 50%를 넘으면 기본값을 뒤집는다. (이건 이벤트 계측 대상)

## D-007 ✅ 곱셈 스코어를 버리고 2축 매트릭스로

**결정** — `Value × Feasibility × Confidence`. ECRS 필터를 랭킹보다 먼저.

**맥락** — 초기 공식 `월환산시간 × 수동도 × 도구연결가능성 × 불편함`의 결함을 BPM 전문가가 해부했다.
- 순수 곱셈이라 한 항이 0이면 전부 0
- 단위가 섞여 척도 해석 불가
- 범위가 가장 큰 항이 랭킹을 지배 → 사실상 시간 순 정렬
- **인시 절감만 본다** — 고객 회신 3일→3시간은 인시 절감 0이어도 최대 가치

그리고 PM이 독립적으로 같은 지점을 지적했다: "자기신고 데이터로 4개 변수를 곱하면 오차가 곱해진다."

**추가 발견** — 자동화보다 **제거**가 잘 팔린다.
> 승인 3단계 중 반려율 0%인 단계는 자동화 대상이 아니라 제거 대상입니다. 제거 후보 리스트가 자동화 후보 리스트보다 훨씬 희소하고 경영진에게 잘 팔립니다.

**뒤집는 조건** — 실측 데이터(D-008의 승격 경로)가 충분히 쌓이면 계수를 재보정한다.

## D-008 ✅ 신뢰도 등급과 실측 승격 경로

**결정** — 모든 추정치에 신뢰도 등급을 붙인다. 자가추정 0.5 / 동료합의 0.75 / 실측 1.0. 상위 후보 5개만 2주간 "했음" 탭 카운터로 실측 승격.

**맥락** — 자기보고 데이터의 왜곡은 피할 수 없다. 특히 **빈도 왜곡이 치명적**이다 — 시간×빈도 곱셈이라 오차가 곱해져 랭킹 상위가 통째로 뒤집힌다.

보정 장치 중 가장 강력한 것은 **총량 정산**이다:
> 그 사람이 적은 모든 흐름의 월환산 합계를 보여주고 "합계 240시간 / 근무 160시간"이라고 되돌려준 뒤 재배분하게 합니다. 개별 추정을 백 번 다듬는 것보다 효과가 큽니다.

그리고 BPM 전문가는 실측 승격 경로를 **"제품의 진짜 해자"**로 지목했다.

**뒤집는 조건** — 없음. 오히려 조기 착수 후보.

## D-009 🔒 담당자는 조직 디렉터리 FK, 자유 텍스트 금지

**결정** — `assigneeId uuid`. 문자열 허용하지 않는다.

**맥락** — 초기 기획은 "자동완성 있는 자유 텍스트"였다. PM 지적:
> "김과장", "김 과장님", "재무팀 김"이 각각 다른 엔티티가 되는 순간, 인계 지도·병목 인물·부서 간 흐름 같은 **이 제품의 유일한 해자가 전부 무너집니다.** 이건 M1급 데이터 모델 결정이지 M4 인증 단계 이슈가 아닙니다.

"인계 자동 추론"을 핵심 가치로 내세워놓고 그 근거를 자유 텍스트로 받으려 한 건 앞뒤가 안 맞았다.

**같은 이유로 도구도 카탈로그 FK**로 간다. `n8n_node_type` 컬럼은 지금 비워두더라도 자리를 잡아둔다 — 자유 문자열로 3개월 쌓이면 익스포터가 전부 퍼지 매칭이 된다.

**뒤집는 조건** — 없다. 오히려 이것 때문에 인증(WorkOS Directory Sync)을 앞당겼다.

## D-010 ✅ 마일스톤을 개발 난이도 순에서 채택 순으로

**결정** — 저장·공유를 M4 → M1으로, 인수인계 문서 내보내기를 M1.5로.

**맥락** — PM과 조직 전문가가 독립적으로 같은 재배열을 제안했다.
> 직원이 자기 이득(공유 가능한 인계 문서)을 손에 쥐기 전까지는 메타데이터를 채울 이유가 없고, 메타데이터 없이는 분석 뷰가 무의미합니다. 순서를 바꾸지 않으면 M3 도달 시점에 데이터가 비어 있을 위험이 큽니다.

**M3 자동화 랭킹은 v1에서 뺐다.** 요약 카드로 축소 — 단계 수, 관여 인원, 도구 수, 부서 간 인계 횟수, 대기시간 총합. "사람들은 여기서 스스로 병목을 찾아낸다."

**뒤집는 조건** — 파일럿에서 메타데이터 입력률이 60%를 넘으면 랭킹을 앞당긴다.

## D-011 ⏳ "n8n 앞" vs "n8n 옆"

**보류** — 현재 로드맵은 M5+에 실행 명세 export를 배치. **M3 완료 시점에 재검토.**

**맥락** — BPM 전문가의 반박이 제품의 종착점을 건드린다.
> 자동화 후보는 대체로 이미 알고 있습니다. 실무자에게 물으면 30초 안에 나옵니다. 병목은 발견이 아니라 실행입니다. **"n8n 앞"이 아니라 "n8n 옆"**에 서서, 후보를 실행 가능한 명세(트리거·입출력·예외·필요 계정/권한)로 떨어뜨려 자동화팀에 위임까지 해야 합니다. **발견 툴만으로는 시장이 얇습니다.**

시장 분석가도 같은 방향을 가리켰다 — 지불 의사가 가장 뚜렷한 지점은 "TOP N + 절감시간 + **n8n 템플릿 연결**".

**보류하는 이유** — 지금 결정할 필요가 없고, 파일럿 데이터가 답을 준다. 자동화 후보가 나왔을 때 조직이 그걸 실행에 못 옮기는 게 병목으로 확인되면 "옆"으로 간다.

**언제 다시 볼 것인가** — 파일럿 4주차 종료 시점, 그리고 M3 완료 시점.

## D-012 ⏳ 제품 이름

**보류** — 유력 후보 **Preflow**("n8n을 열기 *전*"). 확정 전.

`workflow-builder`는 너무 일반적이고 n8n류와 혼동된다. 국내 판매용 병기명으로 한국어 브랜드(흐름결/업무결)를 검토 중.

**언제 결정할 것인가** — M1 착수 전. 도메인·로고·OG 카드가 여기 의존한다.

## D-020 🔒 파랑을 쓰지 않는다

**결정** — 브랜드는 딥 에버그린 `#1F5C46`. 중립은 따뜻한 종이 회색(hue 85~95). 파랑은 팔레트에 없다.

**맥락** — 두 디자이너의 팔레트가 충돌했다. 비주얼 디자인은 "파랑 금지 + 따뜻한 종이 회색", 다이어그램 디자인은 파랑 액센트 + 쿨 그레이.

**팔레트 정체성이 제품 생존에 직결되므로** 비주얼 쪽을 채택하고 다이어그램 노드 색을 재매핑했다.
- 파랑 = "회사 시스템" 인상 → D-002가 막으려는 바로 그 느낌
- 보라 = AI 스타트업 클리셰
- 밝은 민트(#10B981) = 헬스케어·핀테크 클리셰
- **순수 회색 = 화면을 즉시 "시스템"으로 만든다**

**부수 결정** — 작업 노드는 액센트 색을 아예 쓰지 않는다. 기본값에 색을 쓰면 색 예산이 낭비된다.

**뒤집는 조건** — 브랜드 hue는 토큰 1개라 싼 결정이다. 언제든 바꿀 수 있다. 단 **"따뜻한 중립"과 "파랑 없음"은 유지**한다.

## D-021 🔒 집계를 그리지 않는다

**결정** — % 게이지, 도넛 차트, 진행률 바, 리더보드, 팀 평균 비교를 **전 화면 금지 토큰**으로 지정.

`12단계`는 허용(중립적 사실). `완료율 67%`는 불허(**평가**).

**맥락** — 조직 전문가의 "개인 단위 시간 총합을 절대 화면에 표시하지 마세요"를 디자이너가 컴포넌트 금지 목록으로 번역했다. 게이지 하나가 화면에 있으면 그 화면은 평가 도구가 된다.

**예외** — 우상단 완성도 링(단계 수/담당자/시간 채움률)은 **본인만 보는 잠금해제 신호**로 허용. 팀 비교·순위와 절대 결합하지 않는다.

## D-022 🔒 마름모를 쓰지 않는다

**결정** — 노드 3종 모두 같은 크기의 사각 카드(260×76). 구분은 좌측 3px 액센트 바 + 아이콘 + 실루엣 변형의 3중 인코딩.

**맥락** — 전통적 순서도는 분기를 마름모로 그린다. 기각 이유 3개:
1. 텍스트 가용 면적이 bounding box의 50% — **한글 11자짜리 라벨도 안 들어간다**
2. ELK layered는 직사각형 포트 모델을 전제 — 시각적 진입점과 실제 포트 좌표가 어긋나 화살표가 허공에서 꺾인다
3. 폭이 제각각인 도형이 섞이면 레이어별 정렬 리듬이 깨진다

**3중 인코딩인 이유** — 색은 절대 단독 신호가 아니어야 한다(색맹·흑백 인쇄).

## D-023 🔒 노드 크기 260×76 고정

**결정** — ELK에 넘기는 노드 크기는 **렌즈·줌·메타데이터 유무와 무관하게 항상 동일**. 메타 스트립 24px는 비어 있어도 예약한다.

**맥락** — 레이아웃 안정성의 전제다.
> 높이 변동 = ELK 재계산 = 위치 흔들림 = 멘탈 모델 파괴

그리고 가변폭을 허용하면 자동 레이아웃과 내보내기 여백 계산이 전부 여기 의존하게 되어 나중에 못 바꾼다.

## D-024 🔒 타이핑 중에는 레이아웃을 다시 돌리지 않는다

**결정** — 재계산 트리거는 구조 변경뿐(Enter로 줄 생성/삭제, 분기 생성/삭제, 순서 이동, blur). 텍스트 편집은 라벨만 갱신.

**맥락** — 이런 제품이 실패하는 가장 흔한 이유가 레이아웃 점프다. 노드 폭이 고정(D-023)이라 글자 길이가 레이아웃을 흔들 수 없고, 이것만으로 어지러움의 80%가 사라진다.

여기에 **구조 diff 게이트**(위상 해시 비교), **활성 노드 앵커링**(방금 편집한 노드의 화면 좌표 고정), 스테일 결과 폐기를 더한다.

**검증 시점** — 1주차 프로토타입에서 200노드로 확인. 나중에 붙이는 최적화가 아니라 초기 설계 항목이다.

## D-025 ✅ 짜증 플래그는 렌즈 전용

**결정** — 캔버스 기본 렌즈에서 표시하지 않는다. 짜증 렌즈에서만 나타난다.

**맥락** — 두 디자이너가 충돌했다. 비주얼은 "빨강 금지, 뉴트럴 배경 + 도트 강도", 다이어그램은 "노드 우상단 6px 빨강 도트".

빨강으로 칠하면 즉시 "오류/잘못됨"으로 읽히고, 이건 D-021 및 "색은 판단하지 않는다" 원칙과 충돌한다. 그런데 다이어그램 디자이너 본인이 다른 절에서 **"짜증은 렌즈 채널에 배정"**이라고 했으므로, 렌즈 전용으로 통일하면 자기모순도 해소되고 양쪽 원칙도 지켜진다.

# 기술

## D-030 🔒 `graph = derive(tree) ⊕ overrides`

**결정** — 진실의 원천은 `(순서 있는 트리) + (명시적 엣지 집합)`. 그래프는 순수 함수의 결과. 파생 엣지는 저장하지 않는다.

**맥락** — "아웃라인이 SoT냐 그래프가 SoT냐"는 잘못 세운 이분법이었다. 루프·건너뛰기를 명시적 연결로 저장하기로 한 순간 답은 이미 정해져 있었다.

**그래프를 SoT로 두지 않는 이유** — 임의 그래프에는 정규적(canonical) 아웃라인이 없다. 캔버스에서 엣지 하나 잘못 그으면 왼쪽 아웃라인이 통째로 재배열되는 참사가 난다. 비개발자 제품에서 치명적이다.

---

## D-031 🔒 노드 ID를 위치에서 유도하지 않는다

**결정** — 클라이언트가 UUID 발급. `node-1-2-3` 같은 경로 기반 ID를 쓰지 않는다. 자동 생성 노드도 결정적 ID(`join:{branchItemId}`).

**맥락** — 이게 없으면 캔버스 위치 저장, 코멘트, 실행 이력, AI diff, Yjs 병합이 전부 불가능해진다. **BlockNote를 고른 결정적 이유가 `block.id`를 그대로 `items.id`로 쓸 수 있다는 점**이었다.

---

## D-032 🔒 모든 변경을 op으로 기록한다

**결정** — `applyOps(docId, ops[])`. `saveDocument(wholeJson)` 방식을 쓰지 않는다.

**맥락** — 후자로 시작하면 Yjs 전환 시 모든 mutation을 다시 써야 한다. `operations` 어펜드 로그에서 undo/redo, 감사, Yjs 브리지, AI 초안의 "diff 검토 후 적용"이 전부 나온다.

같은 이유로 **fractional index + jitter**(정수 order는 협업 도입 시 리인덱싱 폭풍)와 **tombstone 삭제**(CRDT 전제조건)를 지금 채택한다.

---

## D-033 🔒 `packages/graph-core`를 순수 패키지로 분리

**결정** — `derive()` / `validate()` / ops 리듀서 / `toN8n()`이 여기 산다. React·Drizzle import 금지.

**맥락** — RSC·웹워커·n8n 익스포터·AI 검증기가 모두 같은 함수를 써야 한다. 없으면 익스포터가 로직을 복제하고, AI가 생성한 아웃라인을 서버에서 검증할 수 없다.

**함께 결정** — 골든 픽스처 50+ (아웃라인 → 기대 그래프)를 v1부터. "갈래의 마지막 단계"가 중첩 분기·빈 갈래·조기 종료에서 애매하고, 의도와 그림이 어긋나면 신뢰가 즉시 무너진다.

---

## D-034 ✅ BlockNote를 쓴다 (직접 구현 금지)

**결정** — `@blocknote/react` 0.52.x, 버전 핀 고정 + 어댑터 레이어(`blockToItem`/`itemToBlock`).

**맥락** — 한국어 IME가 결정적이었다. contenteditable 조합 입력은 ProseMirror가 10년 넘게 잡아온 지옥이고, Chrome 업데이트마다 회귀가 난다. 직접 구현하면 그 지옥을 처음부터 다시 겪는다.

**리스크** — 0.x라 API가 흔들린다. 도메인 SoT는 `items` 테이블이지 ProseMirror JSON이 아니라는 선을 지킨다.

**필수 방어** — `keydown.key`로 로직 금지(조합 중 `keyCode 229`가 들어와 `/` 팔레트와 Enter 분기가 오작동), contenteditable에 React controlled value 금지, Playwright CDP `Input.imeSetComposition` 회귀 테스트를 CI에.

**뒤집는 조건** — BlockNote가 유지보수 중단되거나 breaking change가 감당 불가하면 TipTap 직접 사용으로 내려간다. 어댑터 레이어가 그 비용을 줄여준다.

---

## D-035 ✅ tRPC를 쓰지 않는다

**결정** — App Router + Server Actions. 스트리밍 AI와 파일 익스포트만 Route Handler.

**맥락** — 나중 실시간 협업은 어차피 별도 WebSocket(y-websocket / PartyKit)으로 나가서 tRPC가 커버하지 못한다. 레이어를 하나 덜 쌓는다.

---

## D-036 ✅ WorkOS AuthKit

**결정** — 인증은 WorkOS. `server/auth/getCurrentUser()` 한 모듈 뒤로 숨긴다.

**맥락** — SSO보다 **디렉터리 싱크**가 이유다. D-009가 실제 사내 인명부를 요구하고, SCIM/Directory Sync가 그걸 채워준다. 무료 1M MAU라 사내 도구 규모에서 사실상 무과금.

- Clerk — SSO가 Business 플랜이라 비용 절벽
- Auth.js v5 — IdP 하나로 확정이면 충분하지만 SCIM을 직접 만들어야 함

**뒤집는 조건** — `users.external_id`로 IdP subject를 저장해두면 교체가 하루 작업이다.

---

## D-037 ✅ 접기(collapse)를 v1부터

**결정** — 자식 있는 항목은 그룹 노드로 접힌다. 접기 상태는 URL에 저장해 공유 링크에 반영.

**맥락** — 500노드 성능 문제의 진짜 해법이다. 500스텝 다이어그램은 어차피 사람이 못 읽는다. **나중에 추가하면 ID 스킴과 레이아웃 캐시를 다시 손대야 한다.**

---

## D-038 ✅ v1 캔버스는 읽기 전용

**결정** — 캔버스 편집 없음. 노드 클릭 → 아웃라인 스크롤(선택/포커스 동기화)까지만.

**맥락** — "그림을 직접 옮기고 싶다"는 요구는 100% 나온다. 하지만 양방향 편집은 단방향의 3배 비용이고, 아키텍처(D-030~D-032)가 이미 열려 있어서 나중에 역투영만 구현하면 된다.

**뒤집는 조건** — 캔버스 드래그 시도 이벤트가 세션당 1회를 넘으면(= 레이아웃 수용률 지표 미달) 우선순위를 올린다.

# 기능 설계

## D-050 🔒 파서는 미분할로 편향한다

**결정** — 절 분할 임계 `0.75`. 애매하면 쪼개지 않는다. **단 명시적 마커(번호·불릿)는 저자의 의도이므로 100% 따른다.**

**근거** — **분할은 무손실 연산이지만 병합은 손실 연산이다.**
> 한국어 절을 쪼개면 어미를 손봐야 한다(`받아서` → `받아요`). 사용자가 되돌려 합쳐도 **원문이 복원되지 않는다.** 반면 안 쪼갠 문장은 Enter 한 번으로 언제든 쪼개진다.

추정(연결어미)과 의도(번호·불릿)를 구분한 것이 핵심이다.

**뒤집는 조건** — `paste_result_edited.edit_distance_band`에서 "합치기" 방향 수정이 "쪼개기"보다 많으면 임계를 올린다.

## D-051 ✅ 연결어미 단독으로는 절대 쪼개지 않는다

**결정** — 도메인 신호를 2차 증거로 결합한다.
```
어미 강도 + 도구 전환(+0.25) + 담당자 전환(+0.20)
         + 처소 부사구(+0.15) + 양쪽 서술어(+0.15)   → 임계 0.75
게이트 5종: NOUN_GO(재고) · 인용(-다고) · 보조용언(하고 있다) · 준비동사 · 초단문
```

**근거** — 한국어 연결어미(`-고`, `-아서`)는 다의적이라 단독으로는 신호가 못 된다. 그런데 이 제품은 **도구 카탈로그와 조직 디렉터리를 갖고 있다** — 범용 형태소 분석기가 못 쓰는 이점이다.

> "**메일로** 요청 받아서 **엑셀에** 정리하고 팀장님 컨펌 받고 **ERP에** 등록해요" → 매 절마다 도구가 바뀌어 전부 분할
> "**엑셀 열어서 붙여넣고**" → 준비동사 감점(−0.30)으로 유지

## D-052 🔒 파서는 문자열을 자르지 않는다

**결정** — 원문 위 인덱스(스팬)만 다룬다. 노이즈는 삭제가 아니라 `dropped[]`로 **표시**하고 버리는 양에 **35% 예산제**를 건다. `assertLossless()`가 항목·버림·꼬리가 원문을 겹침 없이 분할하는지 검증하고, 실패하면 "원문 1덩어리" 폴백.

**근거** — **원문을 한 글자도 잃지 않는다**가 파싱의 유일한 성공 기준이다. 여기 붙인 `title_drift` 검사가 나중에 **LLM 환각 방어 장치로 그대로 재사용**된다.

## D-053 🔒 "갈래의 마지막 단계"는 단수가 아니라 집합이다

**결정** — `tails: Tail[]`(열린 끝의 집합). 불변식: **`tails`가 비면 `fallbackFrom`이 반드시 설정된다.**

**맥락** — 이게 [ARCHITECTURE.md](./ARCHITECTURE.md) §8 리스크 #1(변환 규칙의 의미론적 모호성)의 근원이었다. 집합으로 정의하면 중첩 분기·빈 갈래·갈래 끝의 분기가 **특별 취급 없이 같은 규칙으로** 풀린다. 불변식이 **"고립된 노드가 절대 안 생긴다"**를 보장한다.

**함께 결정** — 역할은 `kind`가 아니라 **위치의 교대 규칙**으로 정한다: `isCase(x) ⟺ parent.kind='branch' ∧ ¬isCase(parent)`. 타입 3개(D-005)를 유지한 채 갈래 컨테이너를 표현하고, 에디터가 갈래를 `branch`로 넣든 `task`로 넣든 결과가 같다.

## D-054 ✅ 그래프 모호성은 "연결된 쪽"으로 해소한다

| 상황 | 결정 | 근거 |
|---|---|---|
| 모든 갈래가 `end`인데 뒤에 형제가 있음 | 분기에서 직결(`fallthrough`) | **떠 있는 노드는 "고장"으로 읽히고 그 판단은 되돌릴 수 없다** |
| AND 갈래 일부만 `end` | `end`를 무시하고 합류 | 그대로 두면 **교착**이고, 교착은 그림엔 안 보이고 리드타임 ∞로만 터지는 **조용한 실패** |
| XOR의 join 노드 | 만들지 않는다 (AND에만 생성) | 그림 때문이 아니라 `max(각 갈래)`를 계산할 **자리**가 필요해서 |
| `skip` 의미론 | XOR + 암묵적 else. 건너뛰는 대상은 "분기에 매달린 갈래들" | |

## D-055 🔒 `assigneeId = null`은 "모름"이 아니라 "앞과 같음"

**결정** — forward-fill로 해석한다.

**근거** — 메타 카드가 담당자를 **"바뀌는 지점만" 지정**하게 하므로(PRD §4.5) 이게 정확한 해석이고, **인계 지도라는 해자가 여기서 나온다**(D-009).

## D-056 ✅ `derive()`를 증분화하지 않는다

**결정** — 전체 재계산. 대신 `topologyHash`로 **레이아웃(ELK)만** 게이트한다.

**근거** — 실측: **504항목 = 1.54ms.** ELK는 50~1500ms. **1000분의 1을 최적화하는 것은 버그 표면 확대일 뿐이다.**

`topologyHash`는 제목·담당자·시간·`reworkRate`를 **일부러 제외**한다 — 그것들이 바뀌어도 레이아웃은 안 바뀌기 때문이다.

## D-057 🔒 접합 소켓은 임의 아이템에 붙는다 (PRD §4.9 정정)

**결정** — 첫/마지막 노드가 아니라 **아무 단계에나** 붙을 수 있다. 묻는 시점만 경계로 제한한다.

**맥락** — PRD 초안은 "모든 개인 흐름의 첫 노드와 마지막 노드에"라고 적었는데, **시드 접합 지도 20건 중 절반 이상이 중간 단계 접합**이었다. 예: GA-01 「비품 구매」의 지출결의 상신은 14단계 중 13번이다.

## D-058 🔒 자동 매칭 확정은 점수가 아니라 규칙으로만

**결정** — 자동 확정은 **결정적 규칙 단 하나**(상호 실명 지목 + 동일 카탈로그 객체). 나머지는 전부 후보 제시 + 1클릭.

**근거** — **점수 기반 자동 확정을 켜면 오염을 되돌릴 방법이 없다.** false positive를 false negative보다 나쁘다고 판정했다 — 잘못된 링크가 만든 허구의 불일치가 경영진 리포트에 올라가 실제 부서 갈등을 만드는 것이 **이 기능이 폐기되는 단일 시나리오**다.

**목표치** — 자동 확정 precision ≥ 0.98, 30일 절단율 < 5%.

## D-059 🔒 상대에 대한 평가를 수집하지 않는다

**결정** — 수집하는 것은 **자기 관점의 사실**뿐("나는 여기서 2일 기다린다"). 불일치는 두 사람의 자기 기술을 대조해 **시스템이 발견**한다. 노출은 **양방향 대칭**이고, 자유 텍스트(예외 메모·짜증 플래그)는 **어떤 경우에도 상대에게 가지 않는다.**

**근거** —
> **"저쪽이 얼마나 늦나요"를 한 번이라도 물으면, 이후 어떤 노출 정책으로도 정치를 막을 수 없다.**

정치를 막는 방법은 **노출 통제가 아니라 질문 설계**다.

## D-060 🔒 불일치 집계 단위는 접합 인스턴스가 아니라 접합 유형

**결정** — 부서쌍 × 산출물 단위로 집계하고, 노출 조건은 **접합 유형 5건 이상 AND 기여자 5인 이상.**

**맥락** — 5인 미만 차단(D-002)과 접합의 본질적 2인 구조가 충돌한다. 집계 단위를 한 층 올려서 푼다.
`영업 김OO ↔ 재무 박OO의 세금계산서 건` ✗ → `영업→재무 세금계산서 접합: 12건에서 리드타임 인식 차이` ○

## D-061 ✅ 롤아웃 순서는 인원수가 아니라 접합 차수

**결정** — 허브 부서(재무·총무·인사)부터.

**근거** — 접합은 인원에 균등 분포하지 않는다. **시드 접합 20건 중 재무가 한쪽 끝인 게 9건.** → **재무팀 5명만 쓰면 전사 접합의 40%가 한쪽 끝을 확보한다.**

인사팀 우선 파일럿(PRD §6.3)이 **두 번째 근거로도 정당화**됐다.

## D-062 ✅ 짜증 플래그와 비공개 노트는 내보내지 않는다

**결정** — 인수인계 문서·PDF·공유 링크 어디에도 포함하지 않는다. 비공개 노트는 **명시적 승격만** 있고, 렌더 트리에 `privateNote` 필드가 존재하면 **빌드 실패**(경고가 아니라 예외).

**근거** — 실명 도달 금지 원칙이 내보내기에도 적용되고, **감정 표시는 받는 사람에게 실행 가치가 없다.** 대신 소유자에게 되물어 **사람이 문장으로 바꾸게** 한다.

## D-063 ✅ 문서 생성 엔진은 숫자를 새로 만들지 않는다

**결정** — 날짜·금액·규정·계정번호는 **사용자 원문에만** 등장한다. 유일한 예외인 시간 합계도 `적힌 것만 합쳐서 약 3일`처럼 **단서를 생략하지 않는다.**

**근거** — 인계 문서가 틀리면 대개 후임이 물어본다. 그런데 **날짜·금액·규정은 다르다. 잘못된 마감일 하나가 가산세를 만든다.**

**함께 결정** — 금지어 사전은 **생성 문장에만** 적용한다. 사용자 원문은 절대 다시 쓰지 않는다.

## D-064 ✅ 결핍을 두 종류로 나눈다

**결정** — **위험 결핍**(없으면 일을 못 함)은 본문에서 밝히고, **부끄러운 결핍**은 조용히 생략한 뒤 **「이건 물어보셔야 해요」 질문 목록**으로 뒤집어 뒤에 모은다.

**근거** — 결핍 표시는 받는 사람에겐 유용하지만 만든 사람에겐 부끄러움이 된다. 프레이밍을 "당신이 안 적은 것"에서 **"받는 사람이 물어볼 것"**으로 옮기면 둘 다 만족한다.

**뒤집는 조건** — 파일럿 전 5명에게 보여 "부끄럽다"는 반응이 나오면 기본 꺼짐으로 바꾼다.

## D-065 ⏳ DOCX / HWP 파일 생성 미지원

**보류** — v1에서 만들지 않는다. 대신 클립보드에 `text/plain`(마크다운) + `text/html`을 **같이 넣는다** → 한글(HWP)에 붙여넣으면 표와 굵기가 유지된다.

**근거** — "hwp로 주세요"의 실제 요구는 대개 *"한글에 붙여서 결재 양식에 넣겠다"*이고, 그건 복사로 해결된다. 그리고 **파일 내보내기는 문서 부패의 주된 경로다** — 파일을 고치면 원본과 갈라진다.

**언제 다시 볼 것인가** — 파일럿에서 "파일로 주세요"가 3건 이상이면 **DOCX를 먼저**(한글이 docx를 연다). HWP 직접 생성은 그다음.

# 정책

## D-070 🔒 서버는 문서 본문을 스캔하지 않는다

**결정** — 민감정보(주민번호·카드·계좌) 탐지는 **브라우저 안에서만.** 네트워크 호출 0, 판정 결과 무저장. 텔레메트리는 `pii_hint_shown{class}` 하나뿐이고 `actor_pid`·`doc_pid`를 붙이지 않는다.

**근거 3개**
1. **스캔 코드가 존재하면 확장된다**
2. **"문서 #482에 주민번호 3건" 목록이 생기면 관리자가 반드시 요구하고, 그건 문서 목록 요구와 같다**
3. 오탐은 사람이 본다

**함께 결정** — 마스킹이 아니라 **단어 치환**이다. `880101-1******`도 여전히 개인정보다. 그리고 **DPA에 "내용 기반 스캔 미제공"을 우리가 스스로 못 박아** 나중에 유혹에 넘어가지 못하게 한다.

## D-071 🔒 지원용 임시 열람 기능을 만들지 않는다

**결정** — 대체는 **소유자가 시작하는** 15분 진단 세션 + 콘텐츠 없는 진단 번들.

**근거** — 대부분의 SaaS가 만들고 **대부분의 신뢰 사고가 여기서 난다.** 핵심 차이는 **"시작 권한이 우리에게 없다"**는 것.

break-glass는 2인 승인 + 고객사 CPO 동의 + 24h 내 소유자 통지. 비공개 노트는 **break-glass로도 접근 불가.** 분기 투명성 보고서에 실행 횟수 0까지 공개.

## D-072 🔒 온프레미스를 제공하지 않는다

**근거** — 비용이 아니다. **온프레에선 고객사 IT팀이 DB를 직접 봐서 원칙 1이 우리 손 밖에서 깨진다.**

대체: 국외이전 제로 플랜 / 전용 VPC / **BYOK**(고객이 키를 회수하면 우리가 못 읽는다) / 에스크로.

## D-073 🔒 본문 애플리케이션 레벨 암호화를 하지 않는다

**근거** — ALE가 막는 건 DB 파일 유출인데, **실제 위협(내부자·인가 결함·링크 유출)엔 무력하다.** 대신 비공개 노트만 봉투 암호화하고 복호화 함수를 배치·지원·AI 경로에서 **ESLint로 임포트 차단.**

**보안백서 필수 문장** — **"E2E 암호화가 아니다"를 명시한다.** 영업에서 그 한 줄이 가장 비싼 거짓말이 된다.

## D-074 🔒 조직 전체 RAG 인덱스를 스키마에 만들지 않는다

**결정** — AI 단계가 와도 만들지 않는다. 전송은 현재 세션 입력만, 조직·개인 **이중 opt-in**(조직이 켜도 개인이 끄면 안 간다).

**근거** — **관리자 열람권의 검색창 우회로**가 되기 때문이다. 이 설계에서 **가장 되돌리기 비싼 결정.**

## D-075 ✅ 공유 링크 기본 만료를 종류별로 나눈다

| 종류 | 기본 |
|---|---|
| 조직 내 | 30일 |
| 인계 | 14일 |
| **외부** | **7일** |
| 미열람 링크 | **7일 자동 만료** |

토큰 192비트, DB엔 SHA-256만, **URL에 문서 ID 없음.**
**OG 이미지에 본문을 렌더링하지 않는다** — 카톡·슬랙 캐시는 링크를 끊어도 남는다.

## D-076 🔒 퇴사자 문서는 두 겹으로 쪼갠다

**결정** — 프로세스 지식 = 회사, 비공개 노트·짜증 플래그 = 개인.
퇴사 시 **개인 레이어 자동 파기, 본체는 유지하되 이름을 뗀다.** 요구를 기다리지 않고 **90일 후 자동 실행.**

**근거** — 비공개 노트는 "소유자만 본다"는 약속 하에서만 존재했으므로 회사 이전은 **목적 외 이용**이다.

**전제** — 재직 중 전체 삭제 가능 / 퇴사 후 불가라는 비대칭은 **입사 온보딩·약관에 사전 고지해야만 정당하다.**

## D-077 🔒 부서 단위 자동 공유를 만들지 않는다

**결정** — 대안은 **팀 서재**(소유자가 문서 단위로 명시적 게시).

**근거** — **부서장이 그 부서 소속이므로 D-002의 우회로가 된다.** 그리고 조직 개편이 곧 권한 개편이 된다.

**함께 결정** — 전사 공개 문서는 별도 객체로 두고 **복제 승격만** 허용한다. 개인 문서를 전사 공개로 전환하면 *"실제대로 적은 것"이 "회사가 인정한 규정"으로 읽혀* 제품의 핵심 요청과 충돌한다.

## D-078 🔒 관리자 작성 독촉 알림 기능을 만들지 않는다

**근거** — 전제인 **미작성자 명단이 이미 원칙 2 위반**이고, 화자("옆자리 동료")가 무너진다.

## D-079 ✅ 알림 상한과 발송 창

**결정** — 외부 채널 **주 3건**, 같은 종류 **2주 1건**, 발송 창 **평일 09:30–17:30**(조직 설정으로도 22–08시는 못 연다). 주간 다이제스트 대신 **4시간 이벤트 지연 묶음.**

## D-080 ✅ 동료 부정 서술은 삭제도 신고도 아닌 리라이트 제안

# 구현

## D-100 🔒 게이트를 만들 때는 게이트가 살아 있는지 검증하는 테스트를 함께 넣는다

**결정** — 금지 규칙(린트·퍼즈·grep)은 **소스에 실제로 존재하는 문자열**을 대상으로 하고, **의도적 위반 픽스처를 두어 규칙이 그걸 잡는지 확인**하는 테스트를 함께 만든다.

**맥락** — 이 원칙은 **같은 실패를 세 번 겪고 나서** 세워졌다.

| # | 게이트 | 왜 공허했나 |
|---|---|---|
| 1 | `n-400` Stylelint | 문서는 `n-400`이라 부르는데 Tailwind는 **`paper-400`으로 컴파일**한다. 0건 검출, 항상 초록 |
| 2 | k-익명성 퍼즈 테스트 | `round(4/5)*5 = 5`. **라운딩된 값을 검사하면 4명 셀이 통과한다** |
| 3 | `elk.position` 좌표 시드 | `forceNodeModelOrder`가 `semiInteractive`를 지배해 **아무 효과가 없는데** "앵커링의 1차 방어선"으로 문서에 적혀 있었다 |

> **방어하는 척하면서 아무것도 안 막는 것이 방어가 없는 것보다 나쁘다.** 없으면 알고나 있는데, 있으면 안심하기 때문이다.

## D-101 🔒 앵커링은 ELK 옵션이 아니라 뷰포트 역보정으로 달성한다

**결정** — 좌표 시드(`elk.position`)를 넣지 않는다. 테스트로 금지한다. 앵커 고정은 ELK 결과를 받은 뒤 **뷰포트와 노드에 동일한 duration·easing의 CSS 트랜지션**을 걸어서 얻는다.

**근거 (대수적)** — 뷰포트를 즉시 translate하면 앵커가 `z·Δ`만큼 튀었다가 220ms에 걸쳐 되돌아온다. **끝점만 맞고 중간에 왕복한다.**
두 트랜지션의 duration·easing이 같으면 `screen(s) = p_prev·z + T_prev`가 모든 `s`에서 상수가 된다.
→ `setViewport(v, {duration})`은 **금지**한다(d3 기본 easing이라 노드 트랜지션과 다르다). 커밋 순서는 `flushSync(setNodes)` → 뷰포트 transform 직접 DOM 기록.

**부수 결정** — 삭제 시 앵커는 **후속자가 아니라 선행자**로 잡는다(후속자를 잡으면 캔버스가 140px 내려간다).

**⚠️ 구현이 찾아낸 반례 — 표류 가드가 필요하다**

앵커링이 **항상** 옳다고 적었는데 틀렸다. **앵커가 움직인 거의 유일한 노드일 때 앵커링은 해롭다.**

40단계 체인에서 인접한 두 단계를 맞바꾸면 움직이는 노드는 **딱 둘**이다. 편집한 노드를 화면에 고정하려고 캔버스를 140px 밀면, **가만히 있어야 할 나머지 38개가 화면에서 움직인다.**

실측: `jump_score` **0.004 → 0.082** (갈래 많은 60노드 픽스처에서는 0.005 → 0.165).
**보정이 무보정보다 20~33배 나쁘다.**

→ **표류 가드**: 평행이동은 **보이는 생존 노드의 화면상 평균 이동거리를 실제로 낮출 때만** 적용한다. 아니면 `hold`하고 이유를 `'drift'`로 기록한다.
이러면 *"보정 후가 보정 전보다 나빠지는 일"*이 **정의상 불가능**해진다.

`hold`가 정상 결과이므로 `anchorId`와 `rule`을 함께 실어 텔레메트리(`anchor_rule`)에 남긴다 — 대부분의 올바른 결과가 `hold`다.

## D-102 🔒 재배치 커밋에서 줌을 바꾸지 않는다

**근거** — 줌과 위치를 같은 커밋에서 바꾸면 `T(s) = s_a − p(s)·z(s)`가 `s`에 대해 비선형이라 **앵커 고정이 수학적으로 깨진다.** 재배치는 translate 전용.

## D-103 ✅ 사이클은 ELK 기하를 뒤집어 쓰지 않고 사이드 레일로 직접 라우팅한다

**결정** — 우측 사이드 레일 6점 라우팅을 직접 구현한다. 시각 처리는 대시가 아니라 **위치 + `↩` 글리프**.

**근거** — ELK에 back edge를 뒤집어 넘긴 뒤 결과 기하를 그대로 뒤집어 쓰면 화살표가 노드 **하단으로 들어와** "모든 화살표는 위에서"라는 시각 규칙이 깨진다. 대시는 `hold`의 점선 보더와 충돌한다.

다섯 선분이 각각 층간 거터(64px)나 bbox 밖만 지난다는 **노드 비관통 증명**을 표로 첨부한다.

## D-104 ✅ 증분 레이아웃을 하지 않는다

**근거** — `forceNodeModelOrder: true`가 `semiInteractive`를 지배해서 **좌표 시드가 출력에 영향을 주지 않는다.** 증분화의 전제 자체가 성립하지 않는다.

**뒤집는 조건** — (A) `forceNodeModelOrder`를 끄기로 결정 **AND** (B) 200노드에서 ELK가 500ms를 넘김. **둘 다** 충족될 때만.

## D-105 🔒 `topologyHash`만으로는 레이아웃을 게이트할 수 없다 → `layoutKey`

**맥락** — `topologyHash`는 접기 상태·컨테이너 소속·팬아웃 모드·ELK 옵션 변경을 잡지 못한다. 해시가 같아도 재배치가 필요한 케이스가 실재한다.
→ `layoutKey = hash(topologyHash, collapsedSet, containerAssignment, fanoutMode, optionsVersion)`.
재배치가 필요한/불필요한 케이스 **31행 전수표**와 **양방향 CI 테스트**(재배치하면 안 됨 / 해야 함)를 둔다.

## D-106 🔒 내보내기는 화면 캡처가 아니라 커밋된 좌표에서 SVG를 직렬화한다

**근거** — `onlyRenderVisibleElements` 때문에 **화면 캡처는 반드시 노드가 빠진다.** `html-to-image`는 탈출구로만 남기고 함정 10종(line-clamp, clip-path, fontEmbedCSS 캐시, Safari 첫 호출 등)을 문서화한다.

## D-107 ✅ 레이아웃 골든 테스트는 좌표가 아니라 의미 불변식을 고정한다

**결정** — 층 배정, 층 안 좌우 순서, 정상경로 최좌측, 종횡비 ±15% + 하드 불변식(관통·겹침·상단진입). 정확 좌표는 **"ELK가 바뀌었음을 알리는" 카나리아 파일 1개**뿐이고, 실패 메시지가 그렇게 말한다.

**근거** — 좌표를 핀하면 ELK 버전업 때 전부 깨지고, 그러면 사람이 스냅샷을 무비판적으로 갱신하게 된다.

## D-108 🔒 분기 컨테이너는 BlockNote `children`으로 표현한다

**근거** — **IME다.** 평평한 배열 + `parentId`를 얹으면 ProseMirror가 모르는 불변식이 생기고, 그걸 유지하는 `appendTransaction`이 **조합 중에도 돌면서 자모를 날린다.** `children`은 구조가 곧 문서라 유지 트랜잭션이 원리적으로 0줄이다.

**함께 결정** — 확정되지 않은 것은 문서에 넣지 않는다. 도구 배지·인라인 제안 칩·붙여넣기 검토 표시는 **전부 데코레이션**. 분기 컨테이너 하단 버튼줄은 **위젯 데코레이션** — 진짜 블록으로 만들면 그게 `Item`이 되어 버린다.

**함께 결정** — 인라인 제안의 "3초 후 소멸"을 **타이머 트랜잭션으로 하지 않는다.** CSS가 사라지게 하고 플러그인 상태는 다음 트랜잭션에서 게으르게 정리한다. **"3초 뒤 반드시 뭔가를 한다"는 IME와 근본적으로 상극이다.**

## D-109 🔒 `set_title` op은 타이핑 버스트 단위로 만든다

**결정** — 글자마다 만들지 않는다. 경계는 idle 500ms / `compositionend` / blur / 구조 op 직전 / 문장부호.

**근거** — **조합 중 op을 만들면 초성 op이 로그에 영구히 남는다.**

**함께 결정** — **op 입도 ≠ undo 입도.** `txnId`로 레이어를 분리한다. `paste_batch`만 "굵은 op이자 하나의 txn"이고, 그게 허용되는 이유는 **전부 새 UUID라 교환 가능성을 해치지 않기 때문**이다.

## D-110 🔒 모든 필드 op은 `from`(내가 본 값)을 싣는다

**결정** — 3-way merge를 가능하게 한다. 겹치는 편집만 `item_conflicts`(`id = itemId:field`, `variants[]`)에 기록하고, 슬롯엔 서버 승자를, **진 값은 원문 그대로 보존해 동등 위계로 제시**한다. **문자열 이어붙이기를 하지 않는다.**

이게 STATES.md의 *"두 내용 모두 남겨뒀어요"*를 실제로 구현하는 데이터 구조다.

## D-111 ✅ 멀티탭 조율은 Web Locks를 권위로, BroadcastChannel은 전파로

**근거** — 크래시 시 **락이 자동 해제**되므로 하트비트 타임아웃을 추측할 필요가 없고, FIFO 대기열이라 **탭 3개 이상에서도 리더가 둘이 될 수 없다.** 아웃박스가 오리진(IndexedDB) 소유라 죽은 탭의 미전송 op을 승계 탭이 자동 회수한다.

## D-112 🔒 `navigator.onLine`은 `false`만 믿는다

**근거** — 캡티브 포털이 200 OK를 준다. 온라인 판정은 요청 성패 + `x-wf-health` **헤더** 프로브로 한다(바디를 보지 않는다).

## D-113 🔒 거짓말 금지가 "사라질 수 있다는 말을 하지 않는다"보다 상위

**결정** — IndexedDB가 실패한 메모리 폴백 상태에서는 *"이 브라우저에 남아 있어요"*를 **말하지 않는다.** 대신 `[내용 복사해두기]`를 1급 버튼으로 승격한다.

**맥락** — STATES.md의 절대 원칙("내용이 사라질 수 있다는 문장을 쓰지 않는다")은 **실제로 로컬에 남아 있을 때만** 참이다. 원칙을 지키려다 거짓말이 되는 지점을 예외로 판다.

## D-114 🔒 "모두 저장했어요"는 4중 검증을 통과해야 말한다

메모리 큐 / IndexedDB 아웃박스 / `opId` 원장 대조 / **`derive().contentHash` 서버 대조**.
**하나라도 실패하면 토스트를 띄우지 않는다.**

## D-115 🔒 시간 실측에 스톱워치를 만들지 않는다

**근거** — **타이머를 붙이는 순간 D-002가 막으려는 것과 같은 종류의 감시 도구가 된다.**

**대안** — 빈도만 "했음" 탭 카운터로 실측하고 시간은 자가추정에 머문다. 그래서 Confidence를 **가법 분해**한다: 동료합의 +0.25 · 빈도 실측 +0.25 · 시간 실측 +0.25. 0.5/0.75/1.0 세 라벨이 이 조합의 대표점으로 재현되고, **빈도만 실측된 흔한 상태**를 정직하게 표현할 수 있다.

## D-116 🔒 "인력 N명 감축 가능"은 산출 금지 출력

**결정** — 계산을 막는 게 아니라 **출력을 막는다.** 금지 표현 정규식 검사를 렌더 직전에 둔다.

**근거** — 절감 시간 데이터가 있으면 `÷ 연 근무시간`은 한 줄이다. **그 함수를 만들자는 요청은 반드시 온다.**

## D-117 ✅ `RiskValue` 기본값은 0이 아니라 "미산정"

**근거** — 0으로 접으면 **리드타임 가치가 큰 후보가 조용히 순위에서 사라진다.** (신규 입사자 계정 준비: 인시 절감 79만 원 vs 리드타임 가치 270만 원)

## D-118 🔒 k-익명 억제를 라운딩보다 먼저, 퍼즈 검증은 억제 전 원재료와 대조

**결정** — `WHERE contributor_n >= 5`를 먼저, 라운딩은 통과한 셀에만. 라운딩은 **잔차 추론 방어이지 억제 수단이 아니다.**
그리고 **시계열 일관 억제**: 어느 하나의 기간에서든 억제 대상이면 전 기간에서 억제한다(`last365 − last90` 차분 공격 차단).

**함께 결정** — k 판정의 "기여자"는 `owner_id`다. 담당자(`assignee_id`)는 **지목당했을 뿐 동의하지 않은 사람**일 수 있어 **k를 가짜로 채운다.**

## D-119 🔒 패키지 경계 — `graph-core`의 `dependencies: {}`는 영구 계약

zod 스키마를 거기 두라는 요구가 두 곳에서 나왔다. 둘 다 별도 패키지로 분리한다.

| 패키지 | 내용 |
|---|---|
| `graph-core` | 순수 리듀서·derive·metrics. **의존성 0** |
| `sync-protocol` | op zod 스키마 |
| `analytics-schema` | 이벤트 zod 스키마 |
| `sync-client` | 런타임. 어댑터 주입 → Node 시뮬레이션 테스트 가능 |
| `layout-core` | **`elkjs`를 런타임 의존성으로 갖지 않는다** (`ElkNode`를 구조적 타입으로만) |

`layout-core`가 elkjs를 안 무는 이유: 테스트가 워커 없이 돌고, **OG 라우트에 500KB가 안 들어오며**, ELK 교체 시 건드릴 파일이 둘뿐이다.

- 새 결정이 생기면 번호를 이어 붙인다. 번호는 재사용하지 않는다
- 결정을 뒤집으면 원본을 지우지 말고 상태를 바꾸고 이유를 덧붙인다
- **"뒤집는 조건"이 비어 있는 결정은 위험 신호다** — 무엇을 가정하고 있는지 모른다는 뜻이다
