# 접근성 명세

> 최종 갱신: 2026-08-17 · 기준: WCAG 2.2 AA (터치 타깃은 AAA 자발 채택)

**사용자 특성이 이 문서의 전제다.** 영업·인사·재무·총무·물류 전 부서, IT 숙련도 편차 극심, **40~50대 사무직 다수**, 사내 표준 브라우저가 구형일 수 있음. 이 제품에서 접근성은 소수를 위한 배려가 아니라 **주 사용자층의 사용 가능 여부**다.

---

## 1. 키보드 내비게이션

Tab 순서(문서 화면):
```
건너뛰기 링크 → 문서 제목 → 저장 상태(읽기 전용, tabindex=0)
→ 공유 → ••• → [아웃라인 패널] → 리사이저 → [캔버스 진입점] → 하단 상태바
```

| 키 | 동작 | 충돌 검사 |
|---|---|---|
| `Tab` | 랜드마크·컴포넌트 간 이동 | 에디터 안에서는 BlockNote 기본이 들여쓰기다 → **아웃라인 안에서는 Tab=들여쓰기 유지하되 `Esc`로 먼저 "패널 탈출 모드"에 진입**(2.1.2 키보드 트랩 회피). 첫 진입 시 `aria-describedby`로 안내 |
| `Esc` | ① **조합 중이면 IME가 먼저 소비**(가로채지 않음) ② 팝오버/인스펙터 닫기 ③ 에디터 포커스 해제 | **IME 우선. `e.isComposing` 체크 필수** |
| `↑ ↓` | 아웃라인: 줄 이동 / 캔버스: 이전·다음 노드(모델 순서) | |
| `← →` | 캔버스: 형제 갈래 간 이동 | v1은 노드 드래그 비활성이라 충돌 없음 |
| `Enter` | 새 단계 / 캔버스에서는 해당 아웃라인 줄로 포커스 이동 | |
| `Cmd/Ctrl+Z / Shift+Z` | undo/redo (op 단위) | |
| `Cmd/Ctrl+K` | 커맨드 팔레트 | `Cmd+L`·`Cmd+D`와 비충돌 |
| **`Cmd/Ctrl+S`** | **예외적으로 가로챈다** → "이미 저장돼 있어요 · 오후 3:12" 토스트 | **40~50대 사용자는 반사적으로 Ctrl+S를 누르고, 아무 반응이 없으면 저장이 안 됐다고 믿는다.** 이건 접근성이 아니라 신뢰 문제 |
| `Cmd+E / Cmd+F / Cmd+P` | **가로채지 않는다** | 브라우저 기본 동작 보존 |
| `/` | 슬래시 메뉴 | **한글 조합 중 `keyCode 229` 문제** — `keydown`이 아니라 ProseMirror `inputRules`로 처리 |

**모든 단축키에 클릭 가능한 등가 컨트롤이 존재해야 한다.** 단축키 목록은 `•••` → "키보드 단축키" 다이얼로그에 인쇄한다.

### 2패널 포커스 관리

```tsx
<main className="split">
  <section aria-label="업무 흐름 글" id="outline-panel">…</section>
  <div role="separator" aria-orientation="vertical" tabIndex={0}
       aria-label="패널 너비 조절" aria-valuenow={pct}
       aria-valuemin={30} aria-valuemax={60}
       aria-valuetext={`${pct}퍼센트`}
       onKeyDown={/* ←/→ 2%, Home/End 스냅 */} />
  <section aria-label="자동 생성된 다이어그램" id="canvas-panel">…</section>
</main>
```

- **리사이저는 2.5.7(드래그 동작) 대응 필수** — 화살표 키로 조절 가능해야 한다
- 패널 간 이동 전용 키: `F6`(데스크톱 앱 관례) + 커맨드 팔레트 항목
- **선택 동기화**: 아웃라인 줄에 포커스 → 캔버스 노드가 강조되지만 **포커스는 이동하지 않는다.** v1에서 캔버스는 읽기 전용이므로 포커스의 주인은 항상 아웃라인이다
- **2.4.11 포커스 가림 금지**: 상단바 52px가 sticky이므로 모든 스크롤 컨테이너에 `scroll-padding-top: 60px`

## 2. 캔버스 접근성 — 가장 어려운 문제

> **결론: SVG 그래프를 접근 가능하게 만들려 하지 않는다. 동등한 구조를 병행 제공하고, 그쪽을 접근성의 정본(正本)으로 삼는다.**

캔버스 DOM에 aria를 붙이는 접근은 **원리적으로 실패한다**:
1. 2차원 위치가 의미를 갖는다
2. 엣지가 DOM 상 노드와 인접하지 않는다
3. `onlyRenderVisibleElements`로 노드가 DOM에서 사라진다

```tsx
{/* 1) 시각 레이어 — 접근성 트리에서 제외 */}
<div className="canvas" role="presentation">
  <ReactFlow nodesFocusable={false} edgesFocusable={false}
             nodesDraggable={false} aria-hidden="true" … />
</div>

{/* 2) 접근성 정본 — 항상 DOM에 존재. 시각적으로는 토글로 노출 */}
<nav aria-label="다이어그램 · 순서대로 읽기" id="graph-text">
  <p id="graph-summary">
    12단계 · 갈래 2곳 · 기다리는 시간 1곳 · 담당자 4명. 위에서 아래로 이어집니다.
  </p>
  <ol aria-describedby="graph-summary">
    <li>
      <button aria-describedby="n3-rel" data-node="n3">
        <span className="kind">작업</span> 견적서 초안 작성
      </button>
      <span id="n3-rel" className="sr-only">
        2번째 단계 다음. 이어서 4번째 단계로. 담당 김지수. 약 30분.
      </span>
    </li>
    <li>
      <span className="kind">갈래</span> 금액이 500만원 넘나요?
      <ol>
        <li><span className="sr-only">갈래 1, 넘으면:</span> …</li>
        <li><span className="sr-only">갈래 2, 아니면:</span> …</li>
      </ol>
      <p className="sr-only">두 갈래는 7번째 단계에서 다시 합쳐집니다.</p>
    </li>
  </ol>
</nav>
```

### 설계 규칙 5가지

1. **위상 순서 = 아웃라인 모델 순서.** `derive()`가 이미 순서 있는 트리를 갖고 있으므로 토폴로지 정렬을 새로 하지 않는다
2. **갈래는 중첩 `<ol>`**, 합류는 갈래 끝의 문장으로 명시. **그래프의 유일한 비선형 요소가 합류이므로, 이것만 문장으로 처리하면 나머지는 완전한 선형이다**
3. 명시적 엣지(루프·되돌아감)는 목록 항목 안에 "→ 3번째 단계로 돌아감" 링크로. 스킵되는 정보가 없어야 한다
4. **목록을 `sr-only`가 아니라 정식 UI("목록으로 보기" 토글)로 만든다.** 항목 버튼을 누르면 캔버스가 해당 노드로 이동하고 아웃라인 줄로 포커스가 간다 — 시각 사용자에게도 유용하다. **접근성 전용 기능은 반드시 썩는다**
5. 노드 200개 초과 시 그룹(부서) 단위 `<details>`로 접어서 제공

**부수 이득**: ELK가 완전히 실패했을 때의 폴백 UI가 이미 만들어져 있다 ([STATES.md §9](./STATES.md)).

## 3. ProseMirror + 한국어 IME + 스크린리더

- 에디터 루트: `role="textbox" aria-multiline="true" aria-label="업무 흐름 글"` (BlockNote 기본값을 덮어쓴다)
- **조합 중 `aria-live` 전면 침묵.** NVDA/VoiceOver는 조합 중 텍스트 노드 교체를 문자 단위로 다시 읽어 *"ㅎ 하 한 한ㄱ 한개…"*가 된다 → `composingRef.current === true`인 동안 모든 라이브 리전 업데이트를 큐에 쌓았다가 `compositionend` 이후 100ms에 1회로 합쳐 방출
- 노드 생성 안내는 `compositionend` + Enter 이후에만
- **`aria-activedescendant` 금지** — 슬래시 메뉴는 실제 포커스 이동(roving tabindex)으로. **IME 조합 중 activedescendant 갱신은 Chrome에서 조합을 끊는다**
- 스크린리더 가상 커서 모드(NVDA 브라우즈 모드)에서 에디터 진입 시 자동 포커스 모드 전환을 위해 `role="textbox"` 유지 필수

## 4. ARIA 명세

| 컴포넌트 | role / 속성 |
|---|---|
| 저장 상태 | `role="status" aria-live="polite"` ([STATES.md §5](./STATES.md) 규칙) |
| 오프라인 인라인 바 | `role="status"` — **`role="alert"` 금지**(불안 조장 + 포커스 가로챔) |
| 삭제 확인 | `role="alertdialog" aria-describedby` |
| 렌즈 전환 | `role="radiogroup" aria-label="보기 방식"` + 각 `role="radio" aria-checked` |
| 노드 팝오버 | `role="dialog"`가 아니라 `role="tooltip"` + hover/focus 양쪽 트리거 |
| 인스펙터 | `role="complementary" aria-label="단계 자세히"`. **열려도 포커스를 강탈하지 않음** |
| 카드 스택 | `role="group" aria-labelledby={질문 id}` + 화면 전환 시 질문 `<h1>`에 `tabIndex={-1}` 포커스 |
| 완성도 링 | `role="img" aria-label="담당자 9/12칸, 시간 4/12칸"` |
| 갈래 컨테이너 | `role="group" aria-label="갈래: 금액 기준"` |

**포커스 트랩 대상 vs 비대상**

| 트랩함 | 트랩 안 함 |
|---|---|
| 메타데이터 카드 스택 (진짜 모달) | 인스펙터 (사이드 패널) |
| 삭제 확인 다이얼로그 | 온보딩 (모달이 아니라 페이지) |
| 공유 다이얼로그 | 노드 팝오버 |
| 커맨드 팔레트 | 토스트 |

## 6. 모션 민감성

| 모션 | 기본 | `prefers-reduced-motion: reduce` |
|---|---|---|
| **노드 생성** (핵심 순간) | `opacity 0→1 + translateY(4px)` 140ms, 40ms 스태거 | **opacity만 140ms, translate·스태거 제거.** 완전 제거하면 "생겼다"는 인지가 사라져 **이 제품의 핵심 피드백이 죽는다** |
| 재레이아웃 노드 이동 | `transform 220ms ease-flow` | **0ms 즉시 점프** + `role="status"` "그림을 다시 정리했어요" |
| 렌즈 크로스페이드 | 200ms | 0ms |
| 카드 스택 슬라이드 | 200ms | 0ms, opacity만 |
| `fitView` / `setCenter` | 200ms | `duration: 0` |
| 토스트 진입 | 140ms | 0ms (표시 시간은 동일) |
| 엣지 `stroke-dashoffset` | 320ms 1회 | 미실행 |

`useReducedMotion()` 훅으로 통일하고, CSS 안전망을 둔다:
```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

## 7. 확대 400% (1.4.10 Reflow)

1280×1024를 400% 확대하면 CSS 뷰포트가 **320×256**이 된다.

- **2패널은 즉시 붕괴한다.** DESIGN.md의 브레이크포인트가 폭 기준이므로 그대로 `< 768px` = "아웃라인 전용 + 다이어그램 바텀시트"가 된다. **이게 정답이다** — 별도 처리 불필요
- 단 세로 256px에서 상단바 52px + 바텀시트 핸들이 남으면 편집 영역이 100px 미만이 된다 → **세로 `< 480px`일 때 상단바를 스크롤에 따라 숨기되, 저장 상태 텍스트만 하단 고정 12px 바로 이동.** 저장 상태는 어떤 경우에도 사라지면 안 된다
- 모든 레이아웃 단위를 `px` 고정 대신 `rem` + `clamp()`로. 패널 폭 `min 380px`는 `min(380px, 100vw)`로 감싼다
- 2차원 스크롤 금지의 예외는 다이어그램 캔버스(1.4.10 예외: "의미상 2차원 배치가 필요한 콘텐츠") — §2의 텍스트 목록이 대안이므로 정당화된다

## 8. 터치 타깃

- 최소 **44×44 CSS px** (2.5.5 AAA를 자발 채택). 시각 크기 32/36px 컨트롤은 `::after`로 히트 영역 확장
- 예외 검토 지점: 아웃라인 드래그 핸들, 노드 팝오버 닫기, 도구 칩 `+2`, 리사이저(시각 1px / 히트 8px → **터치 환경 24px**)
- 인접 타깃 간 최소 간격 8px. **갈래 컨테이너의 `[+ 경우 추가]` / `[갈래 끝내기]` / 2택 칩이 가로로 붙는 구간이 유일한 위험 지점** → 폭 < 480px에서 세로 스택

## 9. 40~50대 사무직 배려 (표준 너머)

### 폰트 크기 조절 — 제공한다

앱 전용 슬라이더가 아니라 `•••` → **"글자 크기: 보통 / 크게 / 아주 크게"**(15 / 17 / 19px) 3단. `html { font-size }` 조정 + 전 레이아웃이 `rem`이므로 자동 확대.

브라우저 확대와 중복이지만 — **브라우저 확대 기능을 모르는 사용자가 다수**이고, 이 3단 선택지는 그들이 유일하게 찾을 수 있는 경로다.

### hover 의존성 제거

현재 스펙에서 hover에만 있는 정보가 3개다 — 노드 제목 전문 툴팁, 도구 칩 `+2`, 엣지 "왜 생겼나" 설명. **셋 다 클릭/포커스로도 도달 가능해야 한다**(1.4.13).

- 툴팁 지연 **hover 300ms → 150ms**로 단축
- 사라짐은 hover 이탈 후 **400ms 유지**(마우스가 툴팁 위로 이동할 시간)
- 툴팁 자체가 hover 가능해야 하고 `Esc`로 닫힌다

### 클릭 타깃

아웃라인 줄 **전체가 클릭 영역**(텍스트 폭이 아니라 블록 폭 100%). 캔버스 노드는 260×76 전체.

### 실수 복구

- undo 스택 **100 op / 세션 무제한 유지**. 페이지 이탈 후 복귀해도 `operations` 로그에서 마지막 20 op는 되돌릴 수 있다
- **삭제 확인을 3단으로 차등**:

| 대상 | 확인 수준 |
|---|---|
| 1줄 삭제 | 확인 없음 + 4초 토스트 `[되돌리기]` |
| 갈래(자식 포함) 삭제 | **인라인 확인** "이 갈래 안 3단계도 같이 지워져요" `[지우기]` `[그냥 두기]` |
| 문서 삭제 | `role="alertdialog"` + **제목 타이핑 확인 금지**(사무직에게 과한 요구). "30일 안에는 되살릴 수 있어요" 명시 |

- 파괴적 버튼은 danger 배경이 아니라 **danger 텍스트 + `n-450` 보더**. **빨간 채움 버튼은 실수 클릭을 오히려 유발한다**

### "이거 눌러도 되나?" 제거

1. 모든 파괴적 액션에 되돌리기가 있고, **버튼 옆에 그 사실을 미리 인쇄한다**: "지우기 (되돌릴 수 있어요)"
2. 저장이 자동이라는 사실을 **한 번은 명시적으로** 알린다 — 첫 문서 3번째 단계 작성 시 1회성 인라인: "적는 대로 저절로 저장되고 있어요. 따로 저장 버튼을 누르지 않으셔도 돼요."
3. `Ctrl+S` 가로채기 (§1)
4. **아이콘 단독 버튼 금지.** 상단바 `•••` 외 모든 버튼은 텍스트 라벨을 갖는다
5. 공유 상태는 상단바 좌측 `🔒 나만 보기`로 **상시 확인 가능** — 이게 "실수로 공개됐나?" 불안의 유일한 해소책이다
