> 최종 갱신: 2026-08-17 · 대상: 롤아웃 0단계(시드, 2주) · 신규 사용자 첫 화면에 선탑재

## 왜 이 문서가 존재하는가

> **0단계 — 시드 콘텐츠 제작. 도구를 아무에게도 주지 마세요.** 신규 사용자가 처음 보는 화면은 절대 빈 화면이면 안 됩니다. **콜드 스타트는 직원이 아니라 팀이 직접 채워서 푸는 겁니다.**
>
> 그리고: **"이건 콘텐츠 작업이지 개발 작업이 아니고, 그래서 자주 미뤄지고, 그래서 자주 실패합니다."**

그래서 지금 만들어 둔다.

**표기 규칙** — 담당자는 역할명(디렉터리 FK로 치환) · 시간은 로그 버킷 · 빈도는 지난 7일 회상 또는 주기 · 😤는 짜증 플래그 후보

### 스키마 매핑

| 본 문서 표기 | 컬럼 |
|---|---|

| `승인`/`응답`/`시각`/`자원` | `items.attrs.waitFor` = `approval`/`reply`/`time`/`resource` + `avgWaitH`, `timeoutH` |
| `이어짐`/`여기서 끝` | 자식 노드 유무 + `edges.kind = 'suppressed'` |
| `→ N번으로 회귀` | `edges` 명시 엣지 + `items.attrs.returnToItemId` |

| 😤 | `items.painFlag = true` |
| 예외 메모 | 각주 텍스트(승격 전) → 승격 시 명시 엣지 |
| ★ 접합 표기 | 첫/마지막 노드의 **외부 상대 + 산출물** |

### 주의사항 3가지

1. **담당자는 `assigneeId` FK이므로** 시드 투입 전에 `인사담당자`·`회계담당자` 같은 **역할 계정을 디렉터리에 선행 생성**해야 한다. 시드가 자유 텍스트로 들어가면 **"유일한 해자가 무너지는" 상황이 시드 단계에서 발생한다**
2. **`lastConfirmedAt`은 투입 시점으로, `createdBy`는 실제 인터뷰 대상자로.** *"회사가 만든 문서"가 아니라 "우리 팀 ○○님이 적은 문서"로 보여야 첫 화면의 신뢰가 생긴다*
3. **시드 워크플로는 편집 가능해야 하지만 원본은 잠근다.** 칩을 눌러 열면 **fork(복제) 후 자기 문서로 편집.** 시드 원본이 오염되면 다음 신규 사용자의 첫 화면이 망가진다
