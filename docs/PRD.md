# 제품 기획서 (PRD)

> 최종 갱신: 2026-08-17 · 상태: 초안 v0.1 (전문가 패널 8인 검토 반영)

---

## 1. 한 줄 정의

**직원은 "설명하지 않아도 되는 업무 문서"를 얻고, 회사는 "직원이 직접 만든 자동화 백로그"를 얻는다.**

같은 데이터, 두 개의 제품 표면. 이 이중성이 제품의 핵심 구조다.

## 2. 문제 정의

n8n·Zapier 같은 자동화 도구를 도입해도, 정작 **무엇을 자동화할지** 아는 조직이 없다.
기존 해법은 두 극단뿐이다.

| | 방식 | 한계 |
|---|---|---|
| 프로세스 마이닝 (Celonis, 퍼즐데이터) | 시스템 이벤트 로그 분석 | 로그가 없는 업무는 못 봄. 국내 진입 1.5억 원~ |
| 태스크 마이닝 (Scribe, StepHow) | 화면 클릭 캡처 | **브라우저 밖을 못 봄** — 전화, 오프라인 승인, 카톡, 부서 간 대기 |
| 컨설팅 | 인터뷰 | 수천만 원, 1회성, 끝나는 날이 문서 사망일 |

**시장 공백**: 로그에도 화면에도 남지 않는 업무. 이 영역의 유일한 데이터 소스는 **당사자의 기억**이고, 그걸 구조화해 수집하는 제품은 사실상 없다. 그리고 국내 중견·중소기업에 월 수십만 원대 자가진단 제품은 존재하지 않는다.

### 문제의 소유자를 혼동하지 말 것

"내 일이 뭔지 알아야 한다"는 문제의식의 주인은 **자동화를 도입하려는 쪽**(COO, DX 담당, 경영지원)이다. 영업팀 김대리는 자기 일을 안다 — 몸으로. 문서로 없을 뿐이다.

> 그에게 "당신 일이 뭔지 알아야 합니다"는 문제 제기가 아니라 잔소리다.

따라서 직원에게 파는 것은 자동화가 아니다.

## 3. 사용자와 약속

### 3.1 직원 (사용자)

전 부서. 대다수 비개발자. IT 숙련도 편차 극심(엑셀도 버거운 사람 ~ Notion 파워유저).

**약속**: "같은 걸 다섯 번 설명하지 않아도 된다."

즉각적이고 이기적인 이득 — 작성 직후 5분 안에 손에 쥐어야 한다.

- **인수인계 문서 / 휴가 대체자 가이드** 원클릭 생성 (가장 강력. 이것 하나가 나머지 전부보다 채택률에 기여)
- **"내 업무 한 장 요약"** — 1on1, 주간보고, 평가 시즌에 그대로 붙여넣기
- **신입 교육자료** — "그거 어떻게 해요?" 반복 질문 소멸
- **의존성 증명** — "내가 왜 늦는지" 병목의 책임 소재가 문서로 남음

### 3.2 경영진 (구매자)

**약속**: "6개월 내 자동화 후보 30건 식별, 5건 착수, 연 환산 절감 N시간."

절대 약속하지 않는 것: 부서별 인력 효율화 근거, 개인 생산성 가시성, 실시간 업무 현황판.

### 3.3 두 약속이 충돌하지 않게 하는 선

이건 UX 디테일이 아니라 **제품이 살아남느냐의 문제**다. 아래는 아키텍처에 하드코딩한다.

- 개인 문서 = 소유자 + 소유자가 발급한 링크만. **관리자 자동 열람권 없음**
- 관리자가 보는 것은 **집계 뷰뿐**. 단위는 사람이 아니라 **프로세스**
- **5인 미만 그룹은 표시 자체를 차단** (드릴다운 불가, k-익명성)
- 개인이 적은 소요시간·짜증 플래그는 어떤 경로로도 실명 도달 불가
- 이 규칙을 개인정보 처리방침이 아니라 **제품 UI 안에 상시 노출**

> 경영진은 반드시 "부서별로 좀 보면 안 되나"라고 요구한다 — 6개월 안에 온다.
> 그때 거절할 근거를 지금 만들어 두는 것이 이 프로젝트에서 할 수 있는 가장 가치 있는 일이다.
> 한 번 감시 도구로 낙인찍히면 정책을 바꿔도 신뢰는 안 돌아온다.

## 4. 핵심 설계

### 4.1 입력 — 3단 경로

빈 캔버스도, 빈 아웃라인도 주지 않는다. 사람은 업무를 계층 구조로 기억하지 않고 **에피소드로** 기억한다.

```
① 붙여넣기        기존 워드 매뉴얼 / 카톡 인수인계 / 메일 스레드를 붙여넣으면
                  줄바꿈·번호·동사 패턴 규칙으로 단계 후보 분해 (AI 없이 80% 커버)
                          ↓ (없으면)
② 질문 연쇄        한 번에 한 질문. 계층 없음. 실패 불가능.
                  "먼저 무슨 일이 시작되나요?" → "그다음엔요?" → 5~6개
                          ↓ 자동 전환
③ 아웃라인 + 다이어그램   "이렇게 정리해봤어요. 여기서 고칠 수 있어요"
```

**아웃라인은 첫 입력 표면이 아니라 편집기다.** 이게 초기 설계에서 가장 크게 수정된 지점.

### 4.2 분기 — Tab 들여쓰기를 문법에서 뺀다

Tab 들여쓰기로 계층을 만드는 개념을 즉시 이해 못 할 사용자가 **30~50%**로 추정된다. 더 나쁜 건 **실패 모드가 조용하다**는 것 — 잘못 넣어도 화면은 멀쩡히 그려지고, 사용자는 나중에 "이 도구 이상하다"고 결론낸다.

대신 자연어 껍데기가 인쇄된 **컨테이너 블록**:

```
◇ 어떤 기준으로 갈리나요?   [ 내용 분류        ]
  ┃ 만약   [ 단순 문의 ]  라면
  ┃    → 여기에 무엇을 하는지 쓰세요
  ┃ 아니면 [ 복잡 문의 ]  라면
  ┃    → 여기에 무엇을 하는지 쓰세요
  [+ 경우 추가]   [갈래 끝내기 ↵]   ○ 이어짐  ● 여기서 끝
```

- Tab / Shift+Tab은 **동일 동작의 가속기로만** 유지. 유일한 통로로 두지 않음
- "만약", "~인 경우", "아니면", "승인되면" 타이핑 시 → "갈래로 바꿀까요? [예]" 인라인 제안
- **Enter 외의 모든 단축키에는 눈에 보이는 등가 컨트롤이 있어야 한다.** 마지막 줄 아래 상시 노출 버튼 3개: `+ 다음 단계` / `◇ 갈래 만들기` / `⏸ 기다리는 시간`

### 4.3 노드 타입 — 3개, 단 속성으로 표현력을 확장

타입을 늘리면 학습 부담이 늘고, 안 늘리면 실무를 못 그린다. **타입은 3개로 고정하고 문법이 아니라 속성으로 흡수한다.** 이것으로 커버리지가 55~65% → **85%**로 오른다.

| 타입 | 속성 | 커버되는 실무 패턴 |
|---|---|---|
| **작업** `task` | 반려율, 반송 대상 | 재작업 루프 (자동화 ROI 1위) |
| **분기** `branch` | `mode: 택1 / 동시 / 조건스킵` | **AND/XOR 구분** — 없으면 리드타임이 과대 계산되어 분석 뷰가 오염됨 |
| **기다림** `hold` | `waitFor: 승인 / 응답 / 시각 / 자원` + 평균대기 + 타임아웃 | 승인 루프, 에스컬레이션, 월말 마감 |

시작·종료는 자동 생성. **"인계(handoff)"는 타입이 아니라** 담당자 변경으로 자동 추론.

> **판단 근거 (전문가 의견 충돌 해소)**: PM은 "승인"을 3번째 타입으로, 다이어그램 디자이너는 "대기"로, BPM은 대기의 4종 세분화를 주장했다. → `hold` 하나로 묶고 `waitFor` 속성으로 세분화하면 셋을 모두 만족한다. 사용자에게는 "기다림" 하나만 노출되고, 선택하면 "무엇을 기다리나요?"로 자연스럽게 세분화된다.

### 4.4 갈래 합류 — 기본은 합류, 단 항상 눈에 보이게

규칙 (c)의 자동 합류는 반품·반려·이탈 갈래에서 자주 틀린다. 하지만 순수 분기(승인/반려는 `hold`로 분리됨)는 합류가 더 흔하다.

→ **기본 합류 + 갈래 컨테이너 하단에 상시 노출되는 2택 칩**(`○ 이어짐 / ● 여기서 끝`). 숨기지 않는다.

그리고 **"이 연결은 왜 생겼나"를 엣지 호버로 설명**한다(파생 vs 명시). 자동 그래프의 오해석은 수동 드로잉보다 위험하다.

### 4.5 메타데이터 — 작성 중에는 아무것도 묻지 않는다

작성 흐름 안에서 6개 필드를 노출하면 담당자 외에는 **20% 미만** 채워진다. 이유는 게으름이 아니라 (a) 인지 전환 비용 (b) 정확도 불안 (c) 보상 부재.

**2단계 분리**: 흐름을 다 쓰면 → 완료 축하 → *"3분만 더 쓰면 어디를 자동화할지 알려드릴게요"* → **전체화면 카드 스택**(한 화면 한 질문).

| 필드 | 입력 방식 | 설계 근거 |
|---|---|---|
| 담당자 | **조직 디렉터리 FK** (자유 텍스트 금지) | "김과장"/"김 과장님"/"재무팀 김"이 다른 엔티티가 되면 인계 지도라는 유일한 해자가 무너짐 |
| 사용 도구 | 카탈로그 FK + 본문 추출 확인 | "엑셀에 정리" 입력 시 줄 끝에 `Excel?` 배지 → 클릭 한 번. **입력이 아니라 확인** |
| 소요시간 | 로그 스케일 버킷 (1분/5분/15분/1시간/반나절/1일+) | 정밀도를 포기하고 순위 정확도를 삼 |
| 빈도 | **"지난 7일 동안 몇 번 하셨어요?"** | 장기 평균은 절대 묻지 않음. 회상 기간 고정 |
| 😤 짜증 | 1단계부터 상시 노출, 클릭 한 번, 질문 없음 | 시간·빈도보다 신호가 강함. "사람들은 자기 고통을 신고하는 건 기꺼이 한다" |

- 담당자는 전원 "나"로 미리 채우고 **바뀌는 지점만** 지정 (`여기부터 다른 사람인가요?`)
- **"모르겠어요/건너뛰기"를 다른 버튼과 동일한 크기로.** 작게 만들면 이탈
- 보상은 배지가 아니라 잠금 해제 — *"3개만 더 채우면 순위를 계산할 수 있어요"*. 포인트·레벨·스트릭은 이 맥락에서 감시적으로 읽힘

### 4.6 예외를 끌어내는 장치

사람은 자기 업무를 설명할 때 예외를 거의 언급하지 않는다. 그런데 자동화 가치의 상당수가 예외 처리에 있다.

- **존재가 아니라 빈도로 묻기**: *"10번 중 몇 번은 이렇게 안 흘러가나요?"* → 0이라고 답하면 그 자체가 의심 신호
- **극단값 회상**: *"지난달에 이 일 하다가 제일 오래 걸렸던 건은요?"* → 평균을 물으면 해피패스가, 최악 사례를 물으면 예외가 딸려 나옴
- **타입별 자동 트리거**: `hold`+승인 → "반려되면 어디로?" / 외부 대기 → "답 안 오면 며칠 기다리고 뭘 하세요?"
- 예외는 처음부터 "경로"로 그리게 하지 않는다. **텍스트 각주로 받고** 나중에 "이거 경로로 만들까요?"로 승격

### 4.7 자기보고 데이터의 왜곡 보정

| 왜곡 | 크기 | 보정 |
|---|---|---|
| 압축 왜곡 (짧은 건 과대, 긴 건 과소) | ±100~300% | 로그 스케일 버킷 |
| **빈도 왜곡** (시간×빈도 곱셈이라 오차가 곱해짐) | 순위가 통째로 뒤집힘 | 회상 기간 고정 (지난 7일) |
| 사회적 바람직성 (부서마다 방향이 반대) | — | 개인 총합 비표시, 밴드 입력 |

**총량 정산 (가장 강력한 장치)**: 그 사람이 적은 모든 흐름의 월 환산 합계를 되돌려준다.
> *"합계 240시간 / 근무 160시간"* → 본인이 재배분

개별 추정을 백 번 다듬는 것보다 효과가 크다.

**신뢰도 등급 노출**: 자가추정(0.5) / 동료합의(0.75) / 실측(1.0). 상위 후보 5개만 2주간 "했음" 탭 카운터로 실측 승격 — **이 승격 경로가 제품의 진짜 해자다.**

### 4.8 분석 — 곱셈 스코어를 버리고 2축 매트릭스로

기존 초안(`월환산시간 × 수동도 × 도구연결가능성 × 불편함`)의 결함: 순수 곱셈이라 한 항이 0이면 전부 0, 단위가 섞여 해석 불가, 범위가 가장 큰 항이 랭킹을 지배해 사실상 시간 순 정렬, 그리고 **인시 절감만 본다** — 고객 회신 3일→3시간은 인시 절감 0이어도 최대 가치다.

```
Value = (T_touch × F × N_people × 12 × Rate) × SaveRate + LeadTimeValue + RiskValue
   T_touch  : 1회 실접촉시간 (대기 제외)
   N_people : 같은 일을 하는 사람 수 (재사용 배수)
   SaveRate : 수동 0.7 / 반자동 0.4 / 자동 0.1   ← 곱이 아니라 계수

Feasibility = 0.25·규칙결정성 + 0.20·입력구조화 + 0.20·시스템접근성
            + 0.15·(1 − 예외율) + 0.10·표준화 + 0.10·안정성      (각 0~1)

Priority = Value × Feasibility × Confidence
```

**랭킹 이전에 ECRS 필터**를 둔다. *"자동화하기 전에 없앨 수 있는가?"* 승인 3단계 중 **반려율 0%인 단계는 자동화 대상이 아니라 제거 대상**이다. 제거 후보 리스트가 자동화 후보 리스트보다 희소하고 경영진에게 잘 팔린다.

**짜증 플래그는 Value에 곱하지 않는다.** 3번째 축(수용성/챔피언)으로 분리 — 자동화 성공률은 그 사람이 원하는지에 크게 좌우된다.

**직원 화면 프레이밍**: "자동화 후보 3개"가 아니라
> **"당신이 안 해도 되는 일 3가지 — 매주 4시간 30분"**
> 그리고 화면 맨 아래에 사용자가 직접 채우는 빈 칸: **"그 시간에 하고 싶은 일"**

### 4.9 조직 프로세스 조립 — 가장 큰 미개척 기회

전 직원이 각자 자기 관점으로 적으면 "구매 요청" 하나가 요청자·팀장·구매팀·재무팀 4개 조각으로 흩어진다. 이걸 잇는 것이 개인 도구로는 절대 만들 수 없는 가치다.

**조인 키는 "프로세스 이름"이 아니라 핸드오프다.**

- 모든 개인 흐름의 첫/마지막 노드에 **외부 상대**를 붙이게 한다 — "누구에게 무엇을 넘기는가 / 누구로부터 무엇을 받는가". 이게 접합 소켓
- 매칭 신호 가중 결합: ① 산출물 명칭(구매요청서, 품의번호) ② 도구+화면 ③ 상대방 실명/역할 ④ 시간 인접성 ⑤ 어휘 유사도
- **자동 100% 매칭을 노리지 않는다.** 후보 3개 제시 + 1클릭 확정
- **조립 = 성장 엔진**: 저장 시 *"다음은 김팀장님이 하시죠? 초대할까요?"* — 조직 프로세스 조립 메커니즘과 바이럴 루프가 **같은 동작**이다
- 조직 뷰는 **읽기 전용 고정**. 편집은 언제나 각자의 개인 흐름에서만

**불일치는 버그가 아니라 최고의 산출물**:
> "요청자는 2일 걸린다 하고 구매팀은 5일이라 한다"
> "요청자는 견적 2개인 줄 알고 구매팀은 3개를 요구한다"

이 **불일치 리포트를 1급 뷰로** 만든다. Celonis conformance checking의 저비용 대체물이고, 조직이 돈을 내는 지점이다.

### 4.10 문서 부패(decay) 방지

날짜 기반 "6개월 됐으니 검토하세요"는 무시당한다.

- **재사용이 곧 갱신**: 작성한 흐름을 **체크리스트 모드**로 다시 연다(월마감, 온보딩). 여는 순간 틀린 단계가 그 자리에서 고쳐짐. — *"읽을 이유 없는 문서는 반드시 썩는다. 실행에 쓰이는 문서만 산다."*
- **신선도는 문서가 아니라 단계 단위**: 노드마다 `last_confirmed_at`. 30/90/180일 경과 시 점점 흐리게 렌더링 + 분석 스코어 자동 감쇠
- **확인은 마이크로 인터랙션으로**: 문서 전체 리뷰 요청은 응답률 5%. 슬랙 DM으로 **3단계만** 보여주고 `[맞음 / 바뀜 / 이제 안 함]` — 20초짜리는 40~60%
- **이벤트 훅**: 조직 변경, SaaS 계정 해지, 담당자 퇴사 시 관련 노드 자동 stale 표시
- 12개월간 아무도 확인 안 한 문서는 **자동 아카이브**. 살아있는 200개가 죽은 2,000개보다 낫다
- **절대 금지: 버전 승인 워크플로우.** 승인이 붙는 순간 문서는 죽는다

## 5. 경쟁과 포지셔닝

### 5.1 가장 위험한 경쟁자

1. **Notion** — 가장 위험. 직원이 이미 글 쓰는 곳, AI가 Mermaid 출력, DB 속성으로 담당자·시간·횟수 + 롤업. **템플릿 한 장으로 이 제품의 70%가 재현된다.** 부족한 건 아웃라인↔다이어그램 양방향 동기화 하나뿐
2. **Scribe / StepHow** — 기능이 아니라 **입력 비용**에서 이긴다. 적지 않아도 기록됨. 단, 브라우저 밖은 못 봄
3. **Microsoft** — Power Automate Premium($15/유저·월)에 Process Mining 접근 포함. 대기업 구매 담당자에게 추가 벤더 검토를 면제해 줌

### 5.2 해자의 진위 — 냉정하게

| 주장 | 판정 |
|---|---|
| 아웃라인 → 자동 다이어그램 | **해자 아님.** Napkin·Whimsical AI·Notion+Mermaid가 유사 결과. 4~8주면 복제. 단 이들은 "한 번 생성"이라 3주 후 어긋남 → **양방향 유지보수는 6~12개월 리드타임** |
| 자동화 후보 스코어링 | **계산식은 3개월이면 복제.** 복제 불가능한 건 **축적된 데이터** — 전 직원 단계-도구-시간 레코드, 도구명 정규화 사전, 부서 간 중복 단계 그래프 |

**결론: 기능 해자 = 없음. 데이터 자산 해자 = 실재하나, 사용자가 꾸준히 입력할 때만 형성됨.**
즉 이 제품의 방어력 전부가 **"입력 습관 형성"** 이라는 한 점에 걸려 있다.

### 5.3 포지셔닝

> **A안을 헤드라인으로, B안을 무료 진입로로. B는 예산이 없고 C는 사용자가 없다.**

- **A (유료 / 헤드라인)**: "직원들이 직접 만드는, 우리 회사의 자동화 백로그"
- **B (무료 / 진입로)**: "쓰기만 하면 흐름도가 되는 업무 기록 — 인수인계와 온보딩용"
- ~~C (진단)~~: "로그 없이 하는 프로세스 마이닝" — 구매자가 CIO로 좁아지고 자기보고 신뢰도 공격을 받음

### 5.4 이름

`workflow-builder`는 너무 일반적이고 n8n류와 혼동된다. **결정 필요.**

| 후보 | 근거 |
|---|---|
| **Preflow** ★ | "n8n을 열기 *전*"이라는 제품 정의를 그대로 담음 |
| Handoff | 핸드오프가 조인 키이자 핵심 가치 |
| Untangle / ProcessLens / WorkTrace | — |
| 흐름결 / 업무결 | 국내 비개발자 접근성 (병기명) |

### 5.5 비즈니스 모델

시장 가격대는 좌석당 $8~25에 몰려 있다(Miro $8~20, Process Street $12.5, Scribe $13~25, Tallyfy Full $25/Light $8.33).

**단일 좌석 과금은 부적합** — 전 직원이 대상이지만 대다수는 월 1~2회만 쓴다. 좌석당 $12를 300명에게 청구하면 갱신 때 반드시 좌석 축소가 온다.

- **이중 좌석** (Tallyfy 모델): 기록·열람 무료, 관리자·분석 좌석만 $15~25
- **규모 밴드 정액** (Trainual 모델): "100인 이하 월 60만 원" — 국내 중견·중소는 좌석 정산보다 연간 정액 선호(추정)
- **자동화 후보 리포트를 상위 티어에 격리.** 기록은 무료, "TOP N + 절감시간 + n8n 템플릿 연결"이 지불 의사가 가장 뚜렷
- 국내 AI 바우처(최대 3억), 중소기업 디지털 전환 지원(최대 1억)에 **진단+구축 번들**로 얹는 경로 실재

## 6. 로드맵

### 6.1 첫 릴리즈에서 증명할 단 하나의 가설

> 비개발자가 도움 없이 **10분 안에** 자기 업무 하나를 기록하고, 자동 생성된 다이어그램을 **남에게 보여줄 만하다고 판단해 실제로 공유한다.**

"공유했다"까지가 가설이다. 만들었다는 것만으로는 아무것도 증명되지 않는다.

### 6.2 마일스톤

기존 초안은 **개발 난이도 순**이었지 채택 순이 아니었다. 재배열한다.

| | 범위 | 근거 |
|---|---|---|
| **M0** (1주) | 디자인 토큰 확정 · 스키마 · `graph-core` 골격 | 되돌리기 가장 비싼 것부터 |
| **M1** (2.5주) | 붙여넣기 파싱 → 질문 연쇄 → 아웃라인↔다이어그램 **안정적** 연동 · **저장·공유 링크** | 공유가 없으면 M1~M3 가치 측정 불가 |
| **M1.5** (1주) | **인수인계 문서 / 휴가 대체자 가이드 내보내기** · PNG/PDF | 직원의 이기적 이득. 이것 하나가 채택률의 절반 |
| **M2** (1.5주) | 메타데이터 카드 스택 (담당자·도구·시간 3개만) · 😤 플래그 · 댓글/멘션 | 빈도는 프로세스 속성이므로 단계에서 분리 |
| **M3** (1.5주) | **요약 카드** (단계 수 · 관여 인원 · 도구 수 · **부서 간 인계 횟수** · 대기시간 총합) | 랭킹이 아니라 요약. 사람들은 여기서 스스로 병목을 찾음 |
| **M4** (2주) | 체크리스트 모드 · 핸드오프 조립 · 불일치 리포트 | 조직 가치와 성장 루프가 동시에 생기는 지점 |
| **M5+** | 자동화 후보 랭킹(관리자 유료) · n8n 실행 명세 export · AI 초안 생성 | 데이터가 쌓인 뒤 |

**M3 랭킹을 v1에 넣지 않는 이유**: 자기신고 데이터로 4개 변수를 곱하면 오차가 곱해진다. 결과를 사용자가 안 믿는 순간 제품 신뢰도 전체가 깎인다.

### 6.3 롤아웃 (전사 동시 오픈 금지 — 4단계, 6개월)

| 단계 | 기간 | 내용 |
|---|---|---|
| **0. 시드** | 2주 | **도구를 아무에게도 주지 않는다.** 팀이 직접 8~12개 부서 워크플로를 인터뷰해서 대신 작성. 콜드 스타트는 직원이 아니라 팀이 채워서 푼다 |
| **1. 파일럿** | 4주 | **인사팀 또는 경영지원.** 감시자로 의심받는 부서가 먼저 자기 것을 벗으면 "감시 도구" 프레임이 깨진다 |
| **2. 계기 확산** | 6주 | 홍보하지 않고 **이벤트에 얹는다** — 인사이동 인수인계, 신입 온보딩, 감사 대응, 장기휴가. *"workflow-builder 써보세요"*가 아니라 *"인수인계 이번엔 여기에 적어주세요"* |
| **3. 챔피언** | 8주+ | 부서장이 아니라 **질문을 가장 많이 받는 실무자 3~7년차**. 임명하지 말고 로그에서 자연 발생한 사람을 지목. 분기별 자동화 1건 실제 실행 예산 부여 |
| **4. 전사 오픈** | — | "이미 200개 문서가 있고 자동화 3건이 실제로 돌아간 뒤"에만 |

**쐐기는 부서가 아니라 사건이다.** 1차 시나리오: 경영지원/재무의 **월 마감 업무** — 반복성 확실, 도구가 엑셀+메일+카톡이라 프로세스 마이닝의 완전한 사각지대, 매달 반복돼 데이터가 자동으로 쌓임.

## 7. 지표

**North Star: 부서 커버리지** — 최근 30일 내 프로세스를 1개 이상 완성했고, 그 문서가 **타인에게 1회 이상 열람된** 직원의 비율.

MAU는 KPI로 쓰지 않는다. 이 제품은 "1인 1회 작성 후 방치"가 자연 상태다.

| 지표 | 목표 | 비고 |
|---|---|---|
| 첫 다이어그램까지 시간 (중앙값) | ≤ 8분 | |
| 작성 완료율 (5단계 이상 저장) | 60% | |
| **레이아웃 수용률** (세션당 노드 드래그 시도) | < 1회 | 자동 배치 품질의 대리 지표 |
| 공유율 (저장 문서 중 링크 생성) | 30% | |
| **열람자/작성자 비율** | ≥ 3:1 | 유일한 유기적 성장 루프 |
| **D14 재편집률** | 25% | **5% 아래면 이 제품은 "죽은 문서 생성기"다** |
| 90일 부서 커버리지 | 30~40% | 12개월 60% |
| 자동화 후보 → 실제 착수 건수 | 6개월 5건 | 경영진에 팔 수 있는 유일한 숫자 |

현실적 예측: 잘해야 전사 40%가 최소 1개 문서, 그중 20%만 살아있는 문서. **그 정도로 충분하다** — 자동화 후보 발굴은 전수조사가 필요 없고, 40%면 반복업무 지형도의 80%가 드러난다.

## 9. 미해결 결정

1. **제품 이름** — Preflow 유력, 확정 필요
2. **"n8n 앞" vs "n8n 옆"** — 발견 툴만으로는 시장이 얇다는 지적. 종착점을 실행 명세(트리거·입출력·예외·필요 권한) export까지로 잡을지. 현재 로드맵은 M5+에 배치
3. **양방향 편집 시점** — v1은 캔버스 읽기 전용 + 선택/포커스 동기화. 아키텍처는 열어둠 (ARCHITECTURE.md §6)
4. **국내 시장 지불 의사** — 데이터 없음. 파일럿에서 검증
